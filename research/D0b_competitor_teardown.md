## 1. 最重要的三个发现

### 1.1 AEC / ANS 是**全局单实例 + 选择矩阵**,不是每通道
`DSPConfig.xml` 与三份 Module.json 的全局模块表(`ListDspModel`)一致显示:
```
AutoMixer → AEC_Selector(回声消除矩阵) → AEC → ANS_Selector(噪声抑制矩阵) → ANS → MainMixer(矩阵)
```
手册原文佐证:「DSP Controller 中**只有一个回声消除模块**,预置了 2 个本地输入和远端输入混音器实现多路信号参与回声消除」「**只有一个噪声消除模块**,预置了多通道混音器」。
44DA 机型有 `AEC1`+`AEC2` 两个实例(`DspType` 14/15),即"要更多 AEC 就加实例",而非按通道复制。

> **对本项目的意义**:PRD §二.7 字面要求"输入通道每一路必须内置 AEC(512ms)",若照字面实现 = 8 份 512ms 自适应滤波器;竞品(同族老芯片)选择的是 **1-2 份共享 AEC + 路由选择**。这是 D13 预算的量级分水岭(约 8×),**必须在写 AEC 代码前由 CTO/architect 定架构**,见 §5 决策项 ①。

### 1.2 竞品处理器 = **ADI SHARC 21489**(手册 §2.3 规格表)
与我们的 ADSP-21569 同厂同族、**上一代**(21489 为 SHARC 第四代 ~450MHz-ish 档;21569 为 SHARC+ ≤1GHz)。
> **意义**:整套功能(8-16ch 通道链 + automixer + AEC + ANS + 矩阵 + 输出链)在**更弱的同族芯片**上已量产可行 [L4/竞品手册]。这是 DEC-0006 风险①("ITC 数据出自波束场景,本项目算法集是否装得下未证")的一个**强方向性反证**——但注意它的架构是"AEC/ANS 全局单实例",不是 8 路并行,不能直接推论"8 路 AEC 也装得下"。

### 1.3 竞品自报**系统延时 <3ms**(手册 §2.3),我们 PRD 目标 <12ms
> **意义**:PRD 的 12ms 相对宽松;但竞品输出链**未列 FIR 线性相位**(见 §3),而我们 PRD §三.2 要 FIR——FIR 群延迟正是延迟预算的大头。竞品的 3ms 与我们的 12ms 不是同口径,不可直接比较。

## 2. 完整功能地图(竞品实际做了什么)

### 2.1 输入通道链(每通道,顺序即 JSON 顺序)
`InExpander(扩展器) → InCompress(压缩器) → InAGC(自动增益) → InEQ(参量均衡) → AFC(反馈抑制)`

| 模块 | 参数(手册) | 备注 |
|---|---|---|
| 扩展器 EXP | 阈值 / 比率 / 启动时间 / 释放时间 | 明确说明"比率 1:20 即等效噪声门" |
| 压缩器 COMP | 阈值 / 比率(1~20) / 启动 / 释放 / 输出增益;附 G.R.+output 双表 | 限幅器另述:仅阈值+释放,两级(轻限→硬限) |
| 自动增益 AGC | 阈值 / 比率 / **目标阈值** / 启动 / 释放 | 手册定义:AGC = 低阈值+慢时间+低比率的压缩器特例 + 静音检测 |
| 参量均衡 PEQ | **8 段**;类型 PEQ/高低架/高低通;频率 / 增益 / **Q 0.02~50**;每段独立开关 + 总开关 | 信号流图标注"8 段英式 EQ" |
| 反馈抑制 AFC | 见 §2.3 | **每通道 8 个陷波器**(PRD 要求 16) |

### 2.2 全局段
| 模块 | 关键参数 |
|---|---|
| **AutoMixer** | **增益共享型**,最大 16 通道;主控:增益 / **斜率(建议 2.0,范围含 1.0~3.0)** / **响应时间(100-1000ms 最佳)**;通道:自动混音开关 / 闪避优先 / 阈值 / **优先级 0-10(默认 5)**;每通道有**直接输出**(不受自动混音与推子影响,只受静音影响) |
| **AEC_Selector / ANS_Selector** | 选择哪些通道进入共享 AEC/ANS 的路由矩阵 |
| **AEC** | 仅 1 个参数:**非线性滤波 NLP = Conservative / Moderate / Aggressive** |
| **ANS** | **抑制等级 6 / 12 / 18 / 24 / 30 dB**(手册明示"值越大对语音伤害越大") |
| **MainMixer** | 输入×输出 交叉点矩阵,路由+混音双功能;手册强调"设完 automixer/AEC/ANS 后**必须再设矩阵**才有正确路由" |

### 2.3 AFC(反馈抑制)—— 本项目优先级最高,单列
- **机理(手册)**:自动检测反馈频点 → 该点加陷波器 → 首次仅轻衰减 → 若仍反馈则按设定继续加深,直到消失或到最大深度。
- **参数**:
  - **恐慌阈值**:高于此电平"绝对是反馈"→ ①暂时衰减输出增益 ②限制输出电平 ③**提高检测灵敏度**;设 0 = 关闭。
  - **反馈阈值**:低于此电平"绝对不是反馈"(防柔和乐段/低电平嗡声误触发)。
  - **滤波器深度**:单个陷波最大衰减量。
  - **带宽**:**1/10 或 1/5 Oct,恒定 Q**(深度增加不变宽);语音环境+滤波器易用完时建议 1/5 Oct。
  - **预设 4 种**:音乐大房间 / 音乐小房间 / 语音大房间 / 语音小房间。
  - **每个陷波器 3 种模式**:**自动 / 手动 / 固定**(自动=参与循环复用;固定=不被新反馈点占用且重启有效)——**对应 PRD §二.5"三种工作模式"**。
  - **清除**按钮:一键复位全部滤波器。
- **8 个滤波器自动循环复用**;支持"锁定滤波器"防演出中变化;可把滤波器**复制到 EQ 模块**当固定陷波用(扩容手法)。
- 手册给了**完整调试 SOP**(a-f 六步:降增益→清除→设参数→开全部麦→缓升增益至啸叫→等模块动作→重复→最后把恐慌阈值设到略高于期望非反馈信号峰值)。
- 手册的诚实话术值得抄进我们文档:"反馈抑制不会魔法般解决系统设计不良"。

### 2.4 输出通道链
`OutXOver(分频) → OutEQ(均衡) → OutDelay(延时) → OutLimiter(限幅)`

| 模块 | 参数 |
|---|---|
| 分频 XOver | 高通+低通各:频率 / 增益 / **类型 Bessel·Butterworth·Linkwitz-Riley** / **斜率 6·12·18·24·30·36·42·48 dB/Oct**;LR 截止定义 -6dB,Bessel/BW -3dB |
| 输出 EQ | **8 段**(信号流图标注);参数同输入 EQ |
| 延时 | **1~1200 ms**,附米/英尺换算 |
| 限幅 | 阈值 + 释放(两级结构) |
| 输出 | 反相 180° / 静音 |

**竞品输出链没有 FIR 线性相位模块**(PRD §三.2 有)——这是我们相对竞品的功能增量,也是延迟预算的新增负担。

### 2.5 机型差异(三份 Module.json)
| Profile | 通道 | 全局模块 |
|---|---|---|
| Normal | 32 in / 32 out | AutoMixer + AEC×1 + ANS×1 + Matrix |
| Type44DA | 32 / 32 | AutoMixer + **AEC×2** + ANS×1 + Matrix |
| Type64D | **64 / 64** | **仅 Matrix**(输入链退化为 EXP→COMP→EQ,**无 AGC/AFC/AEC/ANS**) |
> 规律:通道数越多,每通道处理越薄,全局重算法直接砍掉——**算力守恒的产品化表现**,与我们 8×8 → 12×12 扩展路线(A7)的取舍逻辑一致。

### 2.6 系统能力(手册 §2.3/§3/§4)
采样 48k/24bit;输入增益档 0~48dB(6dB 步进);+48V 幻象 10mA;频响 ±0.5dB(我们 PRD 要 ±0.3dB);THD+N 0.002%@4dBu;动态范围 106dB(与 PRD >106dB 同档);通道隔离 108dB@1k;最大电平 +15dBu;1U 482×200×45mm;220V/40W。
接口:以太网(内置 web 下载上位机)、RS232、USB 声卡(手册明示 **USB 音频经过 AEC 与 ANS**,用于远程会议)、复位键。
上位机:.NET(需 Microsoft .NET Framework),分 `DSP Controller`(主)/`Pannel`(面板)/`User`+`UserEdit`(用户界面定制)四个可执行体;设备默认 IP 169.254.10.227。

### 2.7 控制协议(手册 §4.2,公开文档)
- 帧头 `0xb3` + 消息类型 + 长度 + **版本号(0=V1 定长12字节 / 1=V2 变长)** + 数据。
- 消息类型:`0x21` 参数控制 / `0x22` 参数获取 / `0x13` 切换场景 / V2 增 `0x74` 其他控制 / **`0x6e` Dante 路由**。
- V1:模块ID(2B)+参数类型(2B)+参数值1(2B)+参数值2(2B);矩阵路由特例三参数打包。
- V2:输入/输出标志 + **起始通道~结束通道**(批量)+ 参数类型 + 连续参数值(每值 2B)。
- **场景号仅 0~15(16 组)** —— PRD 要求 ≥50 组预设,竞品做不到。
- 上位机菜单"帮助→中控命令"可导出 V1 命令码(厂商公开的集成手法)。
- 另有 RS232→UDP 转发章节。

## 3. 与我们 PRD 的逐条差异(**决策输入**)

| 项 | 竞品 [L4] | 我们 PRD | 差异性质 |
|---|---|---|---|
| AEC 部署 | **全局 1-2 实例 + 选择矩阵** | 字面"每输入通道内置" | **架构分水岭,须决策(§5①)** |
| AEC 尾长 | 手册未标 | 512ms | 竞品未公开,无从对比 |
| AEC 可调参数 | 仅 NLP 三档 | 未细化 | 竞品把复杂度藏在内部 |
| ANS | 全局 1 实例,5 档(6~30dB) | 每通道"分级+脉冲抑制" | 我们要求更细,含脉冲(竞品无) |
| AFC 陷波数 | **8/通道** | **16/通道** | 我们翻倍,须核算算力 |
| AFC 模式 | 自动/手动/固定 | "三种工作模式" | **口径吻合,可直接采纳** |
| 输入 EQ | 8 段 | 8 段动态 PEQ | 我们多"动态" |
| 输出 EQ | 8 段 | 10 段 + FIR 线性相位 | 我们更重,延迟预算受压 |
| automixer | 增益共享型,16ch | AM+NOM+优先级分组 | 我们要 NOM 门控口径,竞品是纯增益共享 |
| 预设场景 | **16 组** | **≥50 组** | 我们 3 倍,影响存储与协议字段宽度 |
| 延迟 | 自报 <3ms(无 FIR) | <12ms(含 FIR) | 口径不同,不可直比 |
| 频响 | ±0.5dB | ±0.3dB | 我们更严 |
| AoIP | 协议有 Dante 路由命令 | Dante+AES67 | 同向 |
| 平台 | SHARC 21489 | SHARC+ 21569 | 我们更强一代 |

## 4. 可直接复用的东西(不涉版权,均为思路/参数口径)
1. **AFC 参数体系**(恐慌阈值/反馈阈值/深度/带宽 1-5-1/10 Oct 恒Q/三模式/四预设)——是成熟产品的参数口径,可作我们 D2 参数字典的对标基线(数值仍须自标定)。
2. **AFC 调试 SOP 六步**——可直接改写为我们 D14 的 AFC 验收流程与用户手册章节。
3. **"共享重算法 + 选择矩阵"的架构范式**——算力受限下的经典解法。
4. **automixer 优先级量化关系**(斜率 2.0 时每级优先级差 ≈2dB;3.0 时 ≈4dB)——与 D0 雷达的 Dugan 增益共享数学吻合,可交叉验证我们的实现。
5. **协议 V1/V2 版本位设计**(字节 4 做版本区分、V2 批量通道段)——我们私有协议的版本演进可借鉴这个"不破坏旧集成"的做法。

## 5. 待 CTO 决策项(阻塞 P1/P2)
1. **AEC/ANS 部署架构**:全局共享(竞品路线,省算力、PRD 字面不符)vs 每通道(PRD 字面、算力风险 ~8×)vs 折中(N 实例 + 选择矩阵,N 由 D13 定)。**建议:折中路线,N 由预算决定**——需你拍板方向。
2. **AFC 16 点是否照 PRD 硬做**(竞品 8 点已是成熟量产口径;16 点算力翻倍且陷波过多会伤音质)。
3. **预设 50 组**对存储/协议字段的影响(竞品 16 组),是否维持 PRD 口径。
4. 输出链 **FIR 线性相位是否保留**(竞品没有;它是延迟预算最大单项)。
