#      ⇒ ∴ 本表接受**追加**,⛔ 不接受**删除** —— 删一条 = 让一次撤回消失,须走 lead + 留痕。

# ─────────────────────────────────────────────────────────────
# ⭐⭐ 撤回放在哪里:甲类 / 乙类(2026-08-05,verification 提,lead 立)
# ─────────────────────────────────────────────────────────────
# 甲类 · 可变工作件(设计件 / 交接件 / 增补件 / 台账 / 入口文件)
#   ⇒ 撤回【撤在原处】—— 就地划掉或加标注,⛔ 原文不删
#   ⇒ 理由:今天四处失误同一机制 —— 为了留痕而采用的"只增不改",
#     结构性地保证了【新增不回改】⇒ 解法是把"增"加在"旧"的那个位置上
#
# 乙类 · 身份即不可变(带哈希送审快照 / 预注册 / critic verdict / 事故归档)
#   ⇒ ⛔ 件内一字不动;撤回活在【指向它的索引】里
#   ⇒ 理由(与 LESSONS E-2 同源):预注册的价值【全部来自"它写下时就是那样"】
#     ⇒ 带哈希快照同族 —— 就地加注会毁掉使它成为证据的那个性质
#   ⇒ ∴ 这不是"要不要标注"的取舍,是【两类件的性质不同】
#
# ⭐ 判别式(一句话可判):
#     这份件被引用时,引的是它的【内容】,还是它的【当时状态】?
#       引内容 ⇒ 甲类  ｜  引"当时就是这样" ⇒ 乙类
#
# ⛔⛔ 而乙类有一个必须配套的东西,否则撤回【无处可放】:
#     乙类件不能自带撤回标注 ⇒ 它的撤回只存在于索引里
#     ⇒ ∴ 必须保证【每一份乙类件都有一个已知的索引】
#     ⇒ ⚠ 2026-08-05 那两份快照恰好有(`W1A:207` 就是它们的索引)—— 而那是【运气】
#     ⇒ ⇒ 纪律:**乙类件入库时,同时登记它的索引位置**。⛔ 不得依赖"到时候总能找到"
#
# ⭐⭐ 而实测后补上更对症的一条(2026-08-05,verification `W1C_CLASSB_INDEX_AUDIT.md`):
#     盘点 86 份乙类件 ⇒ 无甲类指向者 12 份(14%)。⛔ lead 预设的"绝大多数没有索引"【不成立】。
#     ⇒ 而高分量那几份的共同点**不是"没人引用"**:
#        **引用它们的人,引的是它们【内容里的数】,而不是它们【作为件】的存在。**
#     ⇒ ∴ 撤回位缺失的真实机制是:**数被搬走了,而件被留下了**
#        —— 数在甲类件里流通,件在乙类目录里静止。
#     ⇒ 那个数一旦被推翻,撤回会写在【搬走它的那份甲类件】里,而**源件不会知道**
#        ⇒ 下一个直接去读源件的人,读到的仍是旧数。
#     ⇒ ⭐ 这才是「静默失效」的确切形态:
#        ⛔ 不是"整份件失效没人知道",是**"件里的某个数失效了,而件本身看不出来"**。
#
#     ⇒ ⇒ **纪律(更便宜、更对症)**:
#        ⭐【凡从乙类件搬一个数进甲类件,**搬的那一处写明来源件**(到文件名,不只到章节号)。】
#        ⇒ 那一处天然就是撤回位,且**由搬数的人在搬的当时写下** = 触发器,⛔ 不是台账。
#     ⚠ 两条并存,⛔ 不互相替代:上一条管【整份件被推翻】,本条管【件里的一个数被推翻】。
#        ⇒ 而 2026-08-05 实际发生的六次限定脱落,**全是后者**。
