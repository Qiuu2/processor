# 治理制度(CONF-DSP-88 版)— 来源分级 + 强制门 + 三道关
> 从 `ee-agent-team-starter/00_governance/GOVERNANCE_EE.md` + `POLICY-PROV-001` **原样继承规则,只把举例落到本域**(会议数字音频处理器:DSP固件/声学算法/AoIP/中控协议/上位机)。
> 规则条文与原文冲突时,以原文为准;本文件是本项目直接加载的治理底座。

## 1. 来源分级 L0–L4(严格度 L0 < L4 < L3 < L2 < L1)
每一个进入 decisions_log/规格/预算表/承诺的数字,必须挂 L 标(例:`全链路延迟 9.8ms [L1 环回实测@48k/64帧块]`)。

| 级 | 本域定义 | 能支撑 |
|---|---|---|
| **L1 实测** | 目标板 profiler 实测算力/内存;AP/声卡环回实测 THD+N/频响/SNR/**全链路延迟**;真会议室实测 AFC 啸叫增益余量、AEC ERLE/双讲;与第三方设备实测 AES67/Dante 互通;真 Crestron/AMX 联调过的协议;OTA 真机(含断电中断)实测 | 任何决策,含不可逆 |
| **L2 仿真/工具** | MATLAB/numpy 滤波器响应与稳定性;用实录房间冲激响应仿真 AEC/AFC;桌面定点-浮点 bit-exact;算法原型处理真实会议录音;桌面基准外推算力 | 强约束可;不可逆须 L2+风险声明+CTO 签字 |
| **L3 解析** | 手算 MIPS(每 biquad 5MAC×fs×ch)、延迟=块长/fs×级数+FIR 群延迟 (N−1)/2/fs、内存=尾长×fs×字宽、EQ 闭式频响 | 方向性;进强约束须挂「待 L1/L2 验证」 |
| **L4 占位** | 芯片 datasheet 标称 MIPS、竞品宣传值(">106dB")、SDK 文档 typical、"512ms 尾长应该够" | 仅探索;绝不作不可逆决策唯一依据;不进 log |
| **L0 目测/听感** | "听感没问题""界面挺流畅""演示时没啸叫" | 仅讨论,严禁任何 LOCKED 决策(比 L4 更严) |

**决策权重红线(按可逆性)**:不可逆→L1(或 L2+签字)｜强约束→L2 起(L3 须挂待验)｜方向性→L3｜探索→L4(不进 log)。**可逆性不得自我降档规避等级。**

## 2. 「不可逆 → L1」触发清单(本项目专属)
下列动作前必须 L1(或 L2+风险声明+CTO 签字)+ 人审签核:
1. **DSP 芯片选型/采购承诺**(算力预算须 L2 桌面基准起,量产选型冻结待 L1 板上实测)
2. **Dante 模块/授权方案选型采购**(烧钱+绑定硬件设计,与 #1 耦合评估)
3. **AES67 互通性对外承诺**(须与第三方设备 L1 实测互通)
4. **全链路 <12ms 写进对外规格**(L1 环回实测前只能标"设计目标 [L3 预算]")
5. **中控协议 v1.0 冻结/对外发布**(第三方中控写死对接码后难改;真机联调 L1+签字)
6. **预设/参数文件存储格式冻结**(OTA 后旧预设必须能载入;版本化+迁移实测 L1)
7. **OTA 机制+bootloader 出厂定稿**(变砖=批量损失;断电/断网中途中断实测 L1+签字)
8. **USB VID/PID 与描述符定稿**(多 OS 实测 L1)
9. **音频指标(±0.3dB/>106dB/>102dB/<12ms)进宣传或合同**(硬件+软件联合指标,须 L1 仪器实测)
10. **量产固件版本发布/出厂烧录**
11. **评估板/样机不可逆硬件动作**(上电/焊接/跳线/烧写熔丝)——走铁律九/C10 清单

## 3. 九铁律(规则原样,举例落域)
1. 数字有来源身份证(L 标)。
2. L3 撑强约束须挂「待 L1/L2 验证」并回填(例:算力预算 L3 手算撑"全功能同开可行",挂待目标板实测)。
3. 不可逆决策 L1 或 L2+签字(例:DSP 选型)。
4. **L1 与已 LOCKED 结论冲突 → 强制重审,禁并存**(例:板上实测算力推翻桌面预算 → 立即重审选型/功能配置,不得"两套口径并存")。
5. **撤回必须全库传播**(声明+全库反扫+逐处加标/删,三步缺一不生效;例:某算法 ERLE 数据作废后反扫所有引用它的规格/汇报)。
6. 外部输入(DSP 资料/上游厂家软件/datasheet/客户反馈)≤24h 入库并标来源/日期/L 级。
7. 关键数字双轨独立工具交叉核(例:延迟预算 手算 vs 仿真;滤波器系数 numpy vs MATLAB)。
8. **未在目标板实测的算力/优化收益,一律标 [L4/待验证],不得计入选型/承诺依据**(例:SIMD/加速器理论加速比、"频域分块能省一半算力")。
9. **硬件不可逆动作闸**:评估板上电/接仿真器/焊接/跳线/烧熔丝前,须有 ①CTO 确认出稿的操作清单 + ②物理版本肉眼确认(丝印 REV,禁预设单一版本接线)+ ③安全硬规矩写入清单;缺一不得指导执行。

## 5. ⭐ 假绿纪律(本域版——最关键)
血泪原则:**验证器在占位/恒等/旧文件上照样 PASS = 假绿,比没验更危险。**
- **测试必须真依赖被测物**:AEC 测试信号若不含回声成分照样 PASS = 没测 AEC;处理链 bypass 时 out==in 证明不了任何模块在工作;A/B bit-exact 若两边跑同一实现 = 恒等假绿。
- **能证伪才算数**:对已知 broken 版(系数置零/模块 stub/尾长砍半),测试必须 FAIL;critic 必须索要这个证伪证据。
- **别静默截断**:测试跳过的通道/频点/场景必须显式 log,否则读起来像全覆盖。
- **工具跑了 ≠ 跑对了**:仿真脚本/工具链执行成功 ≠ 结果正确,关键结果第二条路回验(铁律七)。
- **算法效果宣称须用真实素材**:真实会议录音/实录房间冲激响应,不许纯正弦自证。

## 6. 三道关(每一轮产出,含修正稿,缺一不可)
1. **agent 自验**(桌面测试/自查)= 初筛,NOT 门(同上下文同盲点);
2. **独立 critic**(全新上下文,报告头带 `reviewer: critic @ <精确模型ID> / <日期>`)= **唯一放行门**(in-context 调 critic skill 自审不算);
3. **人审(CTO)** = 常识/量级/方向/口径兜底 + 不可逆门签核。

**放行纪律**:独立 critic verdict 前不得 commit/release/冻结。**不得假设「修过即对」,修正稿同等过三关。**

## 7. 变更审计
任何 LOCKED 项(选型/链序/协议格式/预设格式/关键预算)变更 = decisions_log 记一行(旧→新、日期、原因、谁批),禁静默改。
