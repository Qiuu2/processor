# critic — Skill(v0.1:§4 域清单+C 门为项目推导件;方法论骨架标注来源)
> 结构继承 ITC critic skill(对抗式提问/分级/反馈循环,Claude 通识+ITC 方法论);**§4 九门与 C1-C10 域化是本项目从 PRD 推导、CTO 确认(2026-07-30)的真件**。事故级深度(ITC §12 那种)只能从本项目真实事故累积,不预写。

## 1. 评审流程(每份产出)
收件 → 快扫(完整性/格式/L 标) → C1–C10 逐项(治理 §4,先过这关) → §4 域清单命中项深查 → 对抗式追问(边界/最坏/反例/替代解释) → 跨域一致性 → verdict。
verdict 头:`reviewer: critic @ <精确模型ID> / <日期>`;显式列三道关执行状态;C1/C2/C3/C6/C7/C8/C9/C10 任一 FAIL ⇒ 整体 BLOCKER。

## 2. C1–C10 速查
C1 L标齐 ｜ C2 无"实测"措辞越级 ｜ C3 无 L4 撑不可逆 ｜ C4 L3 撑强约束挂待验 ｜ C5 出处可溯+关键数双轨核 ｜ C6 关键资源量 LOCKED 有 L1、冲突必重审 ｜ C7 撤回全库反扫 ｜ C8 外部输入 24h 入库 ｜ **C9 选型收益闸**(未上目标板实测的算力/加速/算法收益不得计入 DSP/Dante 选型与承诺;评估报告须分离"已坐实"与"[L4/待验证]"两栏) ｜ **C10 硬件不可逆动作闸**(评估板上电/接调试器/焊接/跳线/烧熔丝等物理动作前:CTO 出稿清单+物理版本肉眼确认+安全硬规矩,三缺一=BLOCKER;OTA 发布/协议冻结等发布类走治理 §2 清单+G4/G5,不适用三件套——F-03)。

## 3. 严重度
BLOCKER=安全/不可逆风险/假绿/关键功能不可行,立改 ｜ MAJOR=显著质量风险/缺关键验证,本迭代改 ｜ MINOR=可延期 ｜ INFO=参考。判级依固定标准,同类同级。

## §4. 域清单九门(本项目版:看到这个症状先查这里)
1. **算力/延迟预算门**:任何"全功能同开可行/延迟达标"结论 → 查最坏场景累加(8ch AEC512ms+AFC16点+ANC+动态EQ+automixer 同开)、含中断/搬运开销否、逐项 L 标。**经典陷阱:输出链 FIR 线性相位(PRD §三.2)群延迟 vs 全链路<12ms(PRD §一.4)——512taps@48k 仅此一项 ≈5.3ms [L3 手算]**;见"<12ms + FIR线性相位"并存先索延迟分解表。
2. **自适应稳定性门**:AFC 陷波误杀音乐/语音谐波、AEC 双讲发散或吞近端、AGC 泵效应、噪声门吞字头、automixer 抢麦振荡 → 查双讲/音乐检测设计、误触发场景清单、收敛与失稳判据、最坏房间假设。
3. **参数一致性门**:同一参数在 DSP 模块↔协议指令↔UI 控件↔预设文件 的范围/步进/单位/默认值是否同源引用参数字典;预设加载后 DSP 实态与 UI 显示是否同一来源。
4. **协议健壮性门**:版本字段、字节序、校验、粘包/超长帧、RS232 与 TCP 并发写同一参数的仲裁、断线重连后状态同步。
5. **增益结构/爆音门**:级联削波位置(每级 headroom 交代)、模块开关/预设切换/路由切换的 click/pop 抑制(参数斜坡/淡入淡出)、静音实现位置。
6. **假绿门(本域版,治理 §5)**:AEC 测试信号不含回声照样 PASS=没测;bypass 恒等 out==in 不证明任何模块工作;A/B 同实现自比=恒等假绿;纯正弦自证不算效果;**一律索要 broken 版 FAIL 证据**。
7. **兼容回退门**:协议/预设格式改动是否破坏旧版;OTA 失败回滚路径;8×8 写死假设是否堵死 12×12(通道数参数化);Dante/AES67 固件升级后互通性回归。
8. **指标口径门**:>106dB/±0.3dB/<12ms 等硬件耦合指标有无被软件侧单方承诺;竞品/上游软件观察数据定级是否正确(操作观察=对该软件行为 L1,内部推断=L3/L4)。
9. **安全门**:中控 TCP 无鉴权=局域网任何人可静音全场/改预设;OTA 无签名+回滚=变砖/被刷任意固件;网络暴露面清单(端口/服务/组播)。看到协议规范/OTA 方案先查这三样。

## 5. 跨域一致性(最少检查对)
architect参数字典↔各DSP模块参数表↔D9指令集↔D11控件清单↔预设 schema ｜ D13 预算↔各模块自报算力 ｜ D1 链序↔adaptive-dsp 链序提案(A9)↔实现代码顺序 ｜ 时钟域(PTP/音频主时钟)↔platform-fw 实现↔延迟预算。

## 6. 反馈循环
FAILED→提交者修→**修正稿同等全流程过门**(重点:上轮 findings 逐条闭环+新改动区域);3 次 FAILED→ESCALATE CTO 并附全史。
