# ⭐⭐ 本件为什么在【还没有任何常驻 FAIL】时就先建
# ══════════════════════════════════════════════════════════════
# 今天 C 侧**没有**常驻 FAIL ⇒ 下表是空的 ⇒ 机制在今天是个**空转的恒等式**。
# ⇒ 而它必须**现在**建,理由是【时间窗】,不是完备性:
#
#   设计侧的 EXP-5c(最坏合法增益下噪声底破 PRD)迟早要有 C 侧对应物。
#   ⇒ 它一落地,好版本就带一条如实为 FAIL 的检查。
#   ⇒ 而此刻 `run_kill_matrix.sh` 的旧判据是:
#        阴性对照 = 「好版本必须 exit 0」;杀死 = 「变异 exit ≠ 0」
#     ⇒ ⛔ 好版本一旦带 FAIL,阴性对照当场把整个矩阵**中止**(这一半是安全的);
#     ⇒ ⛔⛔ 而"修好"它最自然的动作是**放宽阴性对照** ——
#        那一刻,那条常驻 FAIL 会被记成**每一个变异的战功** ⇒ N 条假杀伤。
#   ⇒ ⇒ ∴ 这正是设计侧 r16 刚修掉的那条病(critic BLOCKER-2「把功记在错的缺陷上」)。
#
# ⭐ 早做比晚做便宜,而这里是**可算的**:
#   晚做 = 先落地一次假杀伤,再修一次【已经进了归档件与汇报的】杀伤率。
#   ⇒ ∴ 机制必须**先于**第一条常驻 FAIL 到位。⛔ 不是"等它来了再说"。
#

#    ⇒ 回退 = 把"换驱动件/换脚本"这条逃逸路径又开回来。
# ② **本文件名【不带轮次号】** —— 那是 critic D3D4-r3 MAJOR-2 的原因:
#    驱动件是每轮换的,登记若住在带轮次号的文件里,换件时没有任何东西强迫它被带上。
# ③ 增删任何一行 ⇒ 须 lead + 独立 critic,并在此留痕(⛔ 只增不静默改)。
# ④ ⭐ 三种状态各有各的退出码,⛔ 不得合并:
#      登记了、而该检查**不在**判定集合里(被删/改名/退役) ⇒ **退出码 2**
#      登记了、而该检查**PASS**                            ⇒ 退出码 1(基线漂移:它被修好了,
#                                                            是好消息,而须**有意识地**改登记)
#      **未登记**、而好版本上它 FAIL                        ⇒ 退出码 1(未登记的常驻 FAIL)
#    ⇒ ⚠ 「必须存在」与「必须 FAIL」是两件事。若增益结构真被改好,对应检查应当 PASS。
# ⑤ ⭐ 而【机制本身会不会响】不能靠"等它有登记项时再说" ——
#    `check_baseline_mech.sh` 在**临时副本**上注入一条人造常驻 FAIL,逐条验四种走法。
#    ⇒ ⛔ 一个从未被证明会响的机制,与没有机制的区别只在于它让人放心。
