# Part 1 — 制度底座（皇冠，原样继承）

## 一句话内核
**每个数字都带"来源身份证"（L 标），决策权重按来源等级卡死；撤回必须全库传播；产出先过独立 critic 再交人。**

## L0–L4 来源分级（严格度 L0 < L4 < L3 < L2 < L1）
| 级 | 含义 | 能撑什么决策 |
|---|---|---|
| **L1** 实测 | 板上/仪器/measured | 任何决策，含**不可逆** |
| **L2** 仿真/工具 | numpy/MATLAB/COMSOL/桌面跑 | 强约束；不可逆须 **L2+风险声明+CTO 签** |
| **L3** 解析 | 闭式/手算 | 方向性；进强约束须挂「待 L1/L2 验证」 |
| **L4** 占位 | placeholder/stub/未实测收益 | 仅探索；**绝不作不可逆决策唯一依据**；不进 log |
| **L0** 目测 | 拍脑袋/无测量 | **仅讨论，严禁任何 LOCKED 决策**（比 L4 更严） |

红线：不可逆→L1（或 L2+签）｜强约束→L2 起｜方向性→L3｜探索→L4。**可逆性不得自我降档**规避等级。

## 强制门（每份产出/评审逐项 PASS/FAIL + 证据）
C1 数字标了 L 级？｜C2 有没有把 L2/L3/L4 说成"实测"？｜C3 有没有 L4 占位当不可逆唯一依据？｜C4 L3 撑强约束没挂"待验"？｜C5 出处可追溯 + 关键数字第二独立工具交叉核？｜C6 几何/关键尺寸 LOCKED 有 L1 且冲突触发强制重审？｜C7 撤回的数字全库反扫+加标/删？｜C8 外部输入 ≤24h 入库？（C9/C10 = 领域特化的不可逆闸，按项目加）
**C1/C2/C3/C6/C7/C8 任一 FAIL ⇒ 整体 BLOCKER，打回。**

## 铁律（一句话；跨领域通用）
1 数字有来源身份证 ｜ 2 L3 撑强约束须挂待验 ｜ 3 不可逆决策 L1 或 L2+签 ｜ **4 L1 与 LOCKED 冲突→强制重审、禁并存** ｜ **5 撤回必须全库传播（声明+反扫+加标/删，三步缺一不生效）** ｜ 6 外部输入 24h 入库 ｜ 7 关键数字双轨独立工具核 ｜ 8 领域不可逆闸关闭前，未坐实收益一律标 [L4/待验证]、不计入选型/承诺 ｜ 9 不可逆物理动作须先有 CTO 出稿清单 + 版本确认 + 安全硬规矩。

## 三道关（流程闸，非铁律）
任何产出（**含修正稿**）：**自动 verify（初筛）→ 独立 critic 门 → CTO 常识审**，缺一不可。
不得假设"修过即对"（缘起：修正稿自带新错）。**独立 critic verdict 前不 commit/不 release；in-context 自审不算门。**

## 假绿纪律（防"测试通过但什么都没验"）
- **测试必须真依赖被测物**：`out==in` 代数恒等（telescoping）验不了滤波/加速器 → 取依赖被测逻辑的中间值 + **证明占位/置零版会 FAIL**。
- **占位冒充实测**：compute 被 stub（memset0/#else/未接线）还 PASS = L4 冒充 L1 → **必跑占位版确认其 FAIL**。
- **布局敏感 = 读未初始化/越界**：compute 没改、只改无关全局却输出变 → BLOCKER 直到隔离。

## 真正的皇冠 = 文化（比条文更重要）
- **假设皆错**：产出不合格，除非证据支持合格。
- **对现实负责，不对自己的文档负责**：信实物/代码/实测 > 信自己写的文档。
- **主动记录自己被抓的错**：decisions_log 里留着"我过度声明→被收回"的痕（本项目 critic 三次抓到我自编删除清单/存档漏记，都如实入库）。
- **不过度声明、不编造、不甩锅 workflow**。

# Part 2 — Skill 标准化流程（本次才定型）

## 核心理念
**好 skill 从真跑蒸馏，不是坐下写"完美模板"。** 预制模板 = 通用/空洞/易掺错平台料（cosplay）。
critic skill 之所以深，是因为它从事故一条条累积。**⚠ 这是对旧 `GENERATION_PROMPT.md`"各专家 skill 填真实方法"的最大修正：别一次性生成 9 个完美 skill。**

## 何时蒸馏（roadmap#5）
**哪个 skill 要真用了，才把它焊到治理+真料上，边跑边长。** 不主动给休眠领域写 skill。

## 决定"一个 agent 几个 skill"的判据（关键，常被问错）
- **不是按领域大小分**，是按**触发场景 + 是否共享知识**：
  - **一个 skill**：几件事是同一活儿的不同面、共享同一上下文、经常一起用（如 critic 横跨 6 域但只干"守门"一件事 → 一个 skill；DSP 的 FIRA 集成/定点/算力/假绿是一台手术的多个器械 → 一个 skill）。
  - **多个 skill**：任务在不同场景独立触发、彼此不共享知识（如"填表 vs 分析表"）。
- **体量**：SKILL.md 正文 < 500 行。**超了且仍是一个职责 → 渐进披露（拆成 SKILL.md 目录 + reference/*.md，仍是一个 skill），不是拆成多 skill。**

## 蒸馏 SOP（8 步，每步可复用）
1. **判定要不要做**：这个 skill 近期要用吗？不用就挂着。
2. **分类现状**：`grep` 出处引用 / L 标 / 项目真锚（d/尺寸/型号/真 DEC）。三种货色——**真料** / **通用模板**（Claude 已知）/ **虚构**（假 ID/假仪器/假基建）。
3. **挖真料**：派 miner agent 从 memory + handoff + decisions_log 提**逐条带出处**的真本事。
4. **CTO 核"有真料没编造"**：先只看 出处→条目 提纲，人确认。
5. **展开 A/B/C + 已移除**：
   - **A 项目真本事**：每条带 `← 文件:行号`，每个数字挂 L 标。
   - **B 通用骨架**：明标"非本项目蒸馏、Claude 已知"，别当项目本事。
   - **C 缺口**：薄、不编造，要用先补真料。
   - **已移除**：逐条带行号记砍了什么、为什么（**铁律五留痕**）。
6. **独立 critic 全量核**：查①没引入新虚构 ②已移除存档准（逐行号核）③没删真料 ④L 标齐 ⑤没过度声明。
7. **全修 findings**。
8. **CTO 签 + commit**（一个 skill 一条 DEC）。

## 特例
- **休眠领域 / 没真跑** → 只能做**"删假留骨"**（删虚构+假 ID+错产品假设，留诚实薄骨架，A 段明写"域休眠、无真料待激活"）——**做不了"提真"半**。真 A 段等真跑。
- **已成事故金标但超 500 行**（如 critic）→ 渐进披露拆文件，别拆 skill，别急着动（能用就先放）。

## 分类速判表（本项目实测）
| 信号 | 真料 skill | 通用模板 | 虚构 |
|---|---|---|---|
| `← 文件:行号` 引用 | 多 | 0 | 0 |
| L 标 | 多 | 少 | 无/假 |
| 项目真锚(型号/尺寸/真 DEC) | 有 | 无 | 无 |
| 假 ID / 假仪器 / 假 API/总线 | 无 | 无 | **有** |

# Part 3 — 设计新 Agent Team 的提示词

## 用法
新项目仓库里放好 starter kit（本目录），打开 Claude Code，粘贴下面这段。
**这是通用版**（任何领域）；EE 专用版见 `GENERATION_PROMPT.md`（但请叠加下面 ⚠ 的 skill 补丁）。

## 通用团队设计提示词（复制粘贴）

```
你是新项目「<领域>多-Agent 系统」的架构师。仓库里的 ee-agent-team-starter/ 是从一个
硬件研发项目提炼的、经实战打磨的框架+治理。请把【框架+治理】原样继承、把领域落到
<你的领域>，生成一套全新配置。

先读：
- 00_governance/GOVERNANCE_*.md（治理底座，原样加载：L0-L4/铁律/C门/三道关/不可逆-L1/假绿纪律）
- 00_governance/LESSONS_SEED.md（元教训，种进各 agent 的 soul/memory）
- AGENT_TEAM_PLAYBOOK.md（本手册：制度 + Skill 标准化流程 + 本提示词）
- 01_architecture/*（架构/协议/状态机/DAG 骨架——学结构，别抄原领域举例）
- 02_agent_templates/*（四件套模板，当"专家 agent 长什么样"的样例，别照抄内容）

【原样继承（只改举例，别改规则）】
1. 治理全套：L0-L4 分级 / 九铁律 / C 门 / 三道关 / 不可逆→L1 清单 / 假绿纪律。
2. 放行纪律：独立 critic verdict 前不 release/不出图/不 commit；in-context 自审不算门；修正稿同等过门。
3. 总控编排（PM/orchestrator）是唯一对人汇报节点；critic 横切、可直接 rebut 任何 agent。
4. 四件套解剖：profile(身份/职责/接口) / soul(价值观/行为/反模式，种 LESSONS_SEED) /
   skill(方法/清单) / memory(从空开始，只放"新项目，从空累积"+ 元教训链接)。

【按 <领域> 重写】
- critic 的 §4 域清单 + 专项门：按你领域的硬规则重写（等价于本项目的 ERC/DRC/热/EMC/
  假绿——你领域的"看到这个症状先查这里"）。
- 「不可逆→L1」触发清单：列你领域真正一次性、烧钱、难回退的动作（流片/打样/采购/冻结…）。
- 角色-模型表：按你的角色清单。

⚠【Skill 纪律补丁 —— 本手册 Part 2，覆盖旧 GENERATION_PROMPT 的"各专家填真实方法"】
5. 【别一次性写 9 个"完美"专家 skill】——那是 cosplay，会掺错平台/虚构仪器料。
   先给每个专家一个【薄骨架 skill】：A 段留空明写"域未跑、无真料待蒸馏" + B 通用骨架(标注) + C 缺口。
   等某角色真要干活了，再按 Part 2 的蒸馏 SOP 把它焊到真跑上（miner→CTO核→A/B/C→独立critic→commit）。
6. 【一 agent 几个 skill】按"触发场景+共享知识"判，不按领域大小：同一活儿多个面=一个 skill；
   独立触发不共享=多 skill；一个 skill 超 500 行且单职责=渐进披露拆文件不拆 skill。
7. 任何进 skill/log 的数字挂 L 标；不确定就标 L4/待验证，别编。

【产出顺序（强制，别一口气生成）】
先只给我：① 角色清单 + 每角色一句定位 ② DAG 依赖草图 ③ L 分级领域校准表
④ critic §4 域清单骨架（你领域的硬门）——让我确认。
我确认后，再逐个展开 CLAUDE.md / SKILL.md / .claude/team_config.md /
各 agents/<role>/{profile,soul,skill(薄骨架),memory(空)}.md。
skill 正文一律薄骨架，真料留到"要用时蒸馏"。
```

## 给这段提示词的三个提醒
- **先要"提纲"再要"全文"**：让 Claude 先交 角色+DAG+L校准+critic门骨架，你确认后再展开。防一口气生成一堆 cosplay。
- **skill 一开始就该薄**：专家 skill 出生是骨架，不是百科。真本事随真跑长出来。
- **critic 是投资回报最高的一件**：它的 §4 域清单 + 假绿门决定整个团队的守门质量，值得最先focus、也最该从你领域的真事故累积。
```
