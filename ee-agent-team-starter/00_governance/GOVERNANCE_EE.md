# 治理制度（EE 版）— 来源分级 + 强制门 + 三道关
> 这是整套框架的**核心精华**，从音频硬件项目的 POLICY-PROV-001 提炼、翻译到电子/PCB/EDA 域。
> 原文见 `POLICY-PROV-001_ITC_reference.md`（深度参考）。**本文件是新项目直接加载的治理底座。**

## 1. 来源分级 L0–L4（严格度 L0 < L4 < L3 < L2 < L1）
每一个进入 log/规格/BOM/承诺的数字，都必须挂 L 标（例：`热阻 42°C/W [L2 仿真]`）。

| 级 | 定义（EE 口径） | 能支撑 |
|---|---|---|
| **L1 实测** | 板级 bring-up / 仪器测量 / **ERC·DRC·DFM 在当前真网表·真 layout 上跑通** / 供应商实价实货期 | 任何决策，含不可逆 |
| **L2 仿真/工具** | SI·PI·热·EMC 仿真、SPICE、场求解器、桌面脚本算 | 强约束可；不可逆须 L2+风险声明+签字 |
| **L3 解析** | 手算/闭式（分压、功耗、走线阻抗估算） | 方向性；进强约束须挂「待 L1/L2 验证」 |
| **L4 占位** | datasheet typical 值、BOM 占位价、未实测收益、假设 | 仅探索；**绝不作不可逆决策唯一依据** |
| **L0 目测** | 拍脑袋 / 无任何测量 | **仅讨论，严禁任何 LOCKED 决策** |

**决策权重红线（按可逆性）**：不可逆→L1（或 L2+签字）｜强约束→L2 起（L3 须挂待验）｜方向性→L3｜探索→L4（不进 log）。**可逆性不得自我降档规避等级。**

## 2. 「不可逆 → L1」触发清单（EE 专属，= 你的 NPI 多门）
下列动作前**必须 L1（在真实输出文件上验证干净）+ 人审签字**：
- **Gerber / 制造文件出图**（DRC 须在最终 layout 上 clean）
- **打样 / 样板下单**
- **元件采购**（尤其长交期 / MOQ / NRE）
- **BOM 冻结 / EOL 承诺**（供应商可供性 L1）
- **EVT / DVT / PVT 阶段放行**
- **认证送测**（EMC/安规）

## 3. 铁律（EE 版，一句话）
1. 数字有来源身份证（L 标）｜2. L3 撑强约束须挂待验｜3. 不可逆决策 L1 或 L2+签字｜4. **L1 与已 LOCKED 结论冲突 → 强制重审，禁并存**（如实测热点推翻仿真余量）｜5. **撤回必须全库传播**（声明+反扫+逐处加标/删，三步缺一不生效；如某元件 EOL 后全库反扫引用）｜6. 外部输入（供应商报价/datasheet 更新）≤24h 入库并标日期｜7. 关键数字**双轨独立工具交叉核**（如两套场求解器 / 手算 vs 仿真）｜8. **确定性验证器的「假绿」纪律**（见 §5）。

## 4. 强制门 C1–C8（critic 每次评审逐项 PASS/FAIL + 证据）
| 门 | 查什么 | FAIL 级 |
|---|---|---|
| C1 | 进 log/规格/BOM 的数字标了 L 级？ | BLOCKER |
| C2 | 有无 L2/L3/L4 被措辞成「实测/measured」？ | BLOCKER |
| C3 | 有无 L4 占位（datasheet typical / 占位价）作不可逆决策唯一依据？ | BLOCKER |
| C4 | L3 撑强约束却没挂「待验证」？ | MAJOR |
| C5 | 出处可追溯？关键数字第二独立工具交叉核？ | MAJOR |
| C6 | 几何/封装/堆叠 LOCKED 有 L1？L1 与 LOCKED 冲突触发了强制重审？ | BLOCKER |
| C7 | 撤回的数字（改版/EOL）全库反扫+逐处加标/删？ | BLOCKER |
| C8 | 不可逆动作前（Gerber/打样/采购）有出稿清单+版本确认+人审签字？ | BLOCKER |

**红线：C1/C2/C3/C6/C7/C8 任一 FAIL ⇒ 整体 BLOCKER，打回，不得进下一 NPI 门。**

## 5. ⭐ 确定性验证器的「假绿」纪律（本项目最关键，因每个 agent 内含 ERC/DRC/IPC-7351）
血泪教训：**验证器在占位/空网表/旧文件上照样 PASS = 假绿，比没验更危险。**
- **测试必须依赖被测物**：ERC/DRC/DFM 的 PASS 必须证明它**消费的是「当前真网表 / 真 layout」**，不是空的、默认的、上一版的、被 stub 的。
- **能证伪才算数**：对一个已知 broken 的版本，验证器必须 FAIL；对 fixed 版 PASS。critic 必须要求这个「证伪」证据。
- **别静默截断**：BOM 导出/网表比对若丢了元件、跳过了网络，必须显式 `log` 出来——静默截断读起来像「全覆盖」其实没有。
- **工具跑了 ≠ 跑对了**：EDA 脚本/MCP 桥执行成功 ≠ 产出正确，输出必须回验（如导出的 Gerber 用第二工具重开核对层数/孔）。

## 6. 三道关（workflow / 交付物验证闸，= 你的图 ②→③→④）
每一轮产出（**含修正稿**）都可能带新错，三关缺一不可：
1. **agent 自跑 ERC/DRC/DFM = 初筛，NOT 门**（同上下文可被同一盲点污染）；
2. **独立 critic**（全新上下文，报告头带 `reviewer: critic @ <模型> / <日期>`）= **唯一放行门**（agent 自己在上下文里调 critic 技能自审**不算**独立门）；
3. **人审 NPI 门** = 常识/量级/方向/口径兜底 + 签核。

**放行纪律**：独立 critic verdict 前**不得 release/commit/出图**。**不得假设「修过即对」，修正稿同等过三关。**

## 7. 变更审计
任何 LOCKED 项（选型/堆叠/封装/关键网络）变更 = 决策 log 记一行（旧→新、日期、原因、谁批），禁静默改。
