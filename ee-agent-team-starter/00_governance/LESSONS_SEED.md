# 元教训种子（LESSONS_SEED）
> 从上一个多-Agent 硬件项目实战里沉淀的、**域无关**的方法论教训。新项目的 memory 从空开始，
> 但把这几条当「出生即带」的先验，能少走一年弯路。每条都带触发器。

## 验证类
- **自审 ≠ 验证**：agent 在自己上下文里的自检会被同一个盲点污染，甚至撤销自己已做对的纠正。
  → 承重结论**必须过全新上下文的独立 critic**。触发：任何 commit/出图/不可逆动作前。
- **「看着对」≠「实测对」**：源码/网表看着对，不代表板子吐出来对 / Gerber 出对。
  → 没实测/没在真产物上验之前，不能判「无罪」。触发：任何「我读了代码/图，应该没问题」。
- **假绿最危险**：验证器在占位/空输入上也 PASS。→ 必须证明它依赖被测物 + 对 broken 版能 FAIL。
  触发：任何 ERC/DRC/CRC/单元测试「通过」。

## 决策类
- **先找决定性实验/验证**，别先跑一堆重活。上个项目多次「两轮 workflow 之后才等来一个更便宜的决定性
  实验」。→ 动手前先问：**最便宜、最决定性的那一步是什么？** 触发：准备开 workflow / 大仿真前。
- **别过度声明**：每个结论内建 4 查——强度够不够 / 是不是同义反复的假绿 / 前后一致 / 物理前提成不成立。
  触发：写「已确认 / 达标 / 根因是 X」这类话时。
- **别急着把旧结论调和进新发现**：抢一个「干净解释」是过度声明的常见病根，会被独立 critic 拦下。
  触发：新数据来了，你想「这正好说明之前那个结论对」。

## 工程类
- **别静默截断**：丢元件/跳网络/采样/top-N，必须显式 log 出来，否则读起来像全覆盖。
- **有状态自检要 snapshot/restore**：比较两帧/两态必须同 state + 同 input，否则有状态链的比对必假失配。
- **共模抵消只抵消共模**：同环境的 A/B 差是真的，但绝对值里的环境/器件/EQ 分量不会因「同环境」消失。
- **工具跑了 ≠ 跑对了**：脚本/MCP 执行成功不等于产出正确，输出要用第二条路回验。

## 协作类
- **独立 critic 是命门，不是走过场**：上个项目里最严重的错，几乎每次都是 critic（或用户）顶回来的；
  agent 单独自检 0 次自己抓到。→ 把 critic 设成硬门，且**修正稿同等过门**。
- **一个节点对人汇报**：编排 agent 是唯一对人汇报口，避免多头信息不一致；但 teammate 之间可直接互怼。
