## §1 ⛔ 两个角色,分开写(lead 点名:「两个角色写清,⛔ 别混」)

### 1.1 角色 A · **T2 档活支锚点** —— ⛔ **无达标线**

```
它要回答:旁链 float32 FFT 跑一次要多少核心周期(N=1024/2048 等)
判据    **只有有效性判据**,⛔ 没有"够不够好"的门 —— 理由与 T1a-fx 同(v0.2 §3.2):
        给取锚点的内核编一个达标线,不是恒真就是恒假;"够不够好"是下游决策
有效性  v0.2 的 G0–G5 + §5b 四条互核(解析下界 / 反汇编清点 / 双轨计时 / 谐调器)
        + A2 的 V9CHK(EXPECT vs DERIVED 比对)
产出    b_fit(cyc 随 N·log₂N 的拟合斜率)+ 截距 + R² + 95% 区间,标 [L2/CCES 模拟器] 或 [L1/板上]
```

### 1.2 角色 B · **V-9 ②号理由的实验臂** —— ⭐ **有判据,且能双向失败**

```
被检验的主张(W1A v0.6 §3.2 理由②,逐字):
  「SHARC+ 浮点 MAC 与定点同为单周期,**算力预算不变**(§2.1 T2 口径同额)
   **[L4/架构特性,待 cycle 实测佐证]**」
⇒ 它是一个**可证伪的预测**,而且 CTO 已附硬条件:V-9 批了**不等于**②被证,须实测
⇒ ∴ 这个角色**必须有判据** —— 与角色 A 正相反
```

### 1.3 ⛔ 为什么必须分开(混了会怎样)

```
若混成一件:「跑出浮点 FFT 的周期数,并与定点比,若接近则② 成立」
⇒ ⚠ 那会让**角色 A 继承角色 B 的判据** —— 而角色 A 本不该有判据
⇒ ⇒ 后果具体:某天②被证伪(浮点更贵)⇒ 若两角色混着,人会连带认为
     "那个浮点 FFT 的周期数也不可用" —— **而它照样可用**,它就是活支的真实代价,
     只是那个代价比架构侧预期的高。**⇒ 这正是"测量"与"验收"被写进同一个判据的老毛病。**
⇒ ⭐ 而反向也一样坏:②通过 ⇒ 有人会读成"浮点 FFT 的数已验收" —— 它只是与定点接近而已
⇒ ∴ 分开的操作形式:**两个角色写在同一份 CSV 的不同列**,
   `ROLE=anchor_T2live` 与 `ROLE=exp_arm_V9reason2` 各自独立判,⛔ 一个的失败不作废另一个
```

## §2 三臂设计 —— **每次比较只隔离一个变量**

> 若只写"浮点 FFT vs 现有 T2",两臂之间差的**不止是数制**:定点版天生带每级定标(`>>1`),
> 而浮点版本不需要它。⇒ 那样比出来的差,是【数制 + 定标】的合体,②号理由测不准。

| 臂 | 构成 | 用途 | `V9` | `ROLE` |
|---|---|---|---|---|
| **A** | Q31 定点 + 每级 `>> 1` 定标 = **现有 T2,一字不改** | ②的参考臂 | `rejected` | `ref_arm_V9reason2` |
| **B** | float32 + **保留**与 A 结构逐一对应的定标(`* 0.5f`) | ②的实验臂 | `granted` | `exp_arm_V9reason2` |
| **C** | float32 + **去掉**定标(= 自然的浮点实现,**将来真要造的那个**) | **T2 档活支锚点** | `granted` | `anchor_T2live` |

```
A vs B  ⇒ 结构逐一对应,**只差数制** ⇒ 这才是②号理由(MAC 单周期与否)的干净对照
B vs C  ⇒ 只差"有没有定标" ⇒ 量出**浮点省掉定标省了多少**(独立于②,自身有用)
C       ⇒ 活支的真实代价 ⇒ 回填 DEC-0009 T2 档
⇒ ⚠ 三臂**必须同 N 扫描**(N ∈ {256,512,1024,2048},四点,按 v0.2 §3.3 的
  「断言 C ∝ N·log₂N 而不是 ∝ N」)、同内存放置、同 timer、同一份闸门
```

## §3 ⚠⚠ 而参考臂 A 有一个**可能致命**的缺陷,必须在跑②之前排除

**我读了现有 T2 的乘法实现(`t2_fft.c:88-91`,逐字)**:
```c
static int32_t t2_q31_mul(int32_t a, int32_t b)
{
    int64_t p = (int64_t)a * (int64_t)b;
    return (int32_t)(p >> 31);
}
```
```
⇒ 这是**可移植 C 写法**:64 位中间积 + 移位
⇒ ⚠ 而 SHARC 有**原生定点 MAC 指令**。可移植 C 的这一句**未必**映射到那条指令 ——
  它可能被编成一段 64 位乘法仿真序列
⇒ ⇒ ∴ 臂 A 可能测的是「**Q31 乘法的 C 仿真**」,而不是「**SHARC 的定点 MAC**」
```
**⛔ 而误差方向正是最危险的那一侧:**
```
若臂 A 被人为拖慢 ⇒ 「浮点 ≈ 定点」甚至「浮点更快」⇒ ②号理由**看起来被证实**
⇒ 而 ② 正是**已经做出的那个决定**(V-9 批准)的支撑理由之一
⇒ ⇒ 即:**误差方向恰好支持既有结论** —— 与 r76 那个「≥」同型,
     也与 b_fit=0.5 那一侧同型:**对我方有利的方向没有闸**
```
**⇒ ∴ 立为②的前置闸(⛔ 不过则②不得出判定,而角色 A 不受影响):**
```
G6 · 原生 MAC 闸
断言   对臂 A 的内层蝶形做**反汇编清点**(v0.2 §5b.2 的 P2),确认 Q31 乘法
       编成了**原生定点乘/MAC 指令**,而非 64 位仿真序列
不过时 ⇒ ⛔ ②号理由**判定不成立、也不成立其反面** —— 报「参考臂无效,②仍为 [L4]」
       ⛔ 不得报"②被证伪",也不得报"②被证实"
⇒ 这条闸失败时阻止什么:阻止**拿一个被 C 写法拖慢的定点臂,去"证实"一个对我方有利的主张**
```
⚠ **而若 G6 不过,修法不是改判据,是换臂 A 的实现**(用编译器内建/内联汇编写原生 Q31 乘)
—— 而那需要工具链与手册 ⇒ [L4/待核],**⛔ 我不写具体指令名**(与 A2 §2.2 不编 API 名同一条规矩)。

## §4 ②号理由的判据 + 两极值代入

```
被测量  r = cyc_B / cyc_A(同 N、同放置、同闸门下)
判据    **双侧**:0.85 ≤ r ≤ 1.18   ⇒ 判「②在本工作点上成立(浮点与定点同量级)」
        ⚠ 上下限**不对称**是有依据的:架构侧自己给过一个方向性估计 ——
          驳回支「定点 FFT + 块浮点,算力 **+~10-20%**」⇒ 即预期定点略贵
          ⇒ 故容忍 r 略小于 1(浮点略快)到 0.85;而 r > 1.18 就与②直接冲突
        ⚠ 该区间是**我定的** [L3/由架构侧 +10-20% 估计反推],⛔ 非架构侧给定 ⇒ 须其确认
```
**两极值代入(含第三次)**:
```
真该过    ②成立:cyc_B = cyc_A ⇒ r = 1.00 ⇒ 落区间 ⇒ **过**
真该不过①  ②不成立(浮点更贵):cyc_B = 2·cyc_A ⇒ r = 2.00 ⇒ **不过** ⇒ 报②被证伪   ✓ 相反
⭐真该不过② 浮点**快一倍**:cyc_B = 0.5·cyc_A ⇒ r = 0.50 ⇒ **不过**
   ⇒ 为什么这一侧也必须失败:两臂**结构逐一对应、只差数制**,而 SHARC 的浮点与定点
     都是单周期 ⇒ 快一倍**在物理上无处安放** ⇒ 它是**测量出错**(多半是 G6 那条:臂 A 被仿真拖慢)
   ⇒ 若判据写成单侧「r ≤ 1.18 ⇒ 过」,r=0.50 会**静默通过并被读成"②强成立"**
   ⇒ ⇒ 而那正好是**对既有决定有利**的方向 ⇒ 单侧判据在这里等于没有判据
```

## §5 ⛔ 而「+10–20%」那个估计,**本方案测不了** —— 须永久标 [L4]

```
架构侧驳回支原文:「退路 = **定点 FFT + 块浮点**,算力 **+~10-20%**(定标/规格化开销)[L4/粗估]」
⇒ ⚠ 而现有 T2(臂 A)是「Q31 + **每级固定右移**」,**不是块浮点**
  —— 块浮点还要**逐块跟踪指数 + 归一化**,而那正是 +10–20% 被归因的地方
⇒ ⇒ ∴ 臂 A **不是驳回支的忠实模型**,它是"朴素定点 FFT"
⇒ ∴ 要测 +10–20%,须再写一个**块浮点 FFT** —— 而那是**已作废支上的新件**
⇒ ⛔ 我建议不写:V-9 已裁,为落败支新写一个内核是把工时投在不会被造的形态上
⇒ ⇒ ∴ **「+10–20%」应永久保持 [L4/粗估,不可测],并在引用处注明"本项目不打算验证它"**
   ⚠ 这不是遗漏,是**主动的范围决定** —— 写明比留白好
```
**⇒ ⭐ 而这条同时收窄了 A3 §7③ 我自己写的那句**:
```
A3 §7③ 我写:「T2 与未来的浮点 FFT 并排跑,正是检验②的那把尺子」
⇒ **收窄**:它检验的是②的**MAC 同周期**那半句(臂 A vs 臂 B),
  ⛔ 不检验②所依附的「+10–20%」那个数 —— 那半句本方案测不了
⇒ 该收窄按 LESSONS E-2 就地记于此,A3 原文不改
```

## §6 实现要求 —— **单源双编译,让 A2 的机制自动接上**

```
⭐ 臂 B 与臂 C 不写成新文件,而是**同一份源码按 typedef 切换数制**:
     typedef int32_t t2_elem_t;   /* 臂 A */
     typedef float   t2_elem_t;   /* 臂 B/C */
     #define T2_MUL(a,b)   /* 定点:64 位中间积>>31 ｜ 浮点:a*b */
     #define T2_SCALE(v)   /* 臂A: (v)>>1 ｜ 臂B: (v)*0.5f ｜ 臂C: (v) */
⇒ 好处三条:
  ① 结构逐一对应**由构造保证**,不靠"我写得一样"(= §2 那条要求的实现形式)
  ② A2 的 `W1C_IS_FLOAT(t2_elem_t)` **自动**推出 V9_BRANCH ⇒ 标签不可能与代码不符
  ③ 改数制只改一行 typedef ⇒ 三臂共享全部闸门与扫描表
⚠ 而 `T2_SCALE` 在三臂间不同 ⇒ **它必须进工作点向量并逐行打印**,
  否则"臂 B 与臂 C 差在哪"在 CSV 上不可见(= 我在 B-2 抓到的「判定与数据分离」同型)
```
