## §0 为什么补的是「它掉了会怎样」这一列

```
原件里每条软处都有 L 标与"待谁确认" —— 那些是**给作者看的**

⇒ ∴ 本表的承重列不是 L 标,是**后果列**
⇒ 而这条本身是今天六次同型事故的共同解:`≥` / 7.4 / 「唯一被声明可能超」/ 「仿真器连不上」
  / 「无论往哪边裁必有废支」/ CLAUDE.md:9 —— **每一次掉的都是限定,不是数**
```

## §4 ⚠ 我对 lead「送审快照不加标注」那条处置的意见:**同意,并建议立成两类件**

> lead 的处置:`submissions/W1A_v0.6_*` / `v0.4_*` 这类**带哈希的送审快照**⛔ 不就地加标注 ——
> 理由:「它们的身份**就是那个哈希**,就地加注会毁掉使它们成为证据的那个性质」
> ⇒ 撤回只能活在**指向它的索引**里(即 `W1A:207`)

**✅ 我同意,理由与本项目已有的一条纪律同源**:
```
LESSONS E-2 已写:**⛔ 不得改写预注册段** —— 预注册的价值**全部来自"它写下时就是那样"**
⇒ 带哈希的送审快照是同一族:**它的价值也全部来自不可变**
⇒ ∴ 不是"要不要标注"的取舍,是**两类件的性质不同**
```
**⇒ 建议立成通用形式(供 lead 定夺)**:
```
甲类 · **可变工作件**(设计件 / 交接件 / 增补件)⇒ 撤回**撤在原处**(加标不删)
乙类 · **身份即不可变**(带哈希送审快照 / 预注册 / 评审 verdict / 事故归档)
       ⇒ ⛔ 件内不动,撤回活在**指向它的索引**里
判别式(⭐ 一句话可判):**这份件被引用时,引的是它的【内容】还是它的【当时状态】?**
   引内容 ⇒ 甲类   ｜   引"当时就是这样" ⇒ 乙类
```
⚠ **而乙类有一个必须配套的东西,否则会漏**:
```
乙类件不能自带撤回标注 ⇒ **它的撤回只存在于索引里**
⇒ ∴ 必须保证**每一份乙类件都有一个已知的索引** —— 否则撤回就无处可放
⇒ 而本轮恰好有:`W1A:207` 是那两份快照的索引 ⇒ 成立
⇒ ⛔ 但这不是普遍成立的 ⇒ 建议:乙类件入库时**同时登记它的索引位置**
```
