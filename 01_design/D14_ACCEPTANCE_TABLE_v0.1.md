## §1 ⛔⛔ 先说三条:**PRD §一.1 的三个指标,各缺一个维,而缺的维各不相同**

> PRD §一.1 原文 [L1/PRD 原文入库件]:
> 「音频规格:48kHz采样,24bit/32bit浮点DSP运算,**频率响应20Hz–20kHz ±0.3dB**,**动态范围＞106dB**,**信噪比＞102dB**」
>
> **⇒ 三个数,三个不同的缺维。⛔ 缺维不补,测出来的数没有意义 —— 而且不会自己暴露。**

### 1.1 动态范围 —— 缺【路由维】(**已由 critic 定位,而台账未回填**)

```
✅ 已定案(DEC-0022,2026-08-04 CTO 拍板):计权口径 = A 计权;对外规格按 min 档器件重定
⛔ 而 DEC-0022 的「依据数字」栏写的是 **整机 typ 107.8 / min 102.7 dB(A)** ——
   那是 **1 进 1 出** 模型的值(架构侧 v0.57)
⛔ 而**同日** critic BLOCKER-1 + 架构侧 v0.61 已加上路由维:
     DR = −10log₁₀(N·10^(−DRadc/10) + 10^(−DRdac/10))
     min 档 N=1/2/4/8 ⇒ **102.67 / 99.82 / 96.89 / 93.93 dB(A)**
     ⇒ 8 路混音(= 本产品 8×8 的定义形态)比 1 路差 **8.74 dB**
⇒ ⇒ **∴ DEC-0022 依据栏的数已被同日的 BLOCKER 超越,而台账未回填**(铁律五:撤回/更正须全库传播)
⇒ 若有人照 DEC-0022 写规格,会写出一个**只在 1 进 1 出成立**的数,而用户的正常用法就比它差 8.74 dB
```
**⇒ 验收表的处置(⛔ 我不替 CTO 选档)**:
```
① 动态范围一行**拆成一族**,按混音路数 N 分档验收:N ∈ {1, 2, 4, 8} 各一行
② 每个数**四个限定同出**:计权口径 / 器件档(min|typ) / 前端是否计入 / **路由配置 N**
③ ⚠ 架构侧 v0.61 MAJOR-1 提议「**不选 A 计权,两个都标**」(依据 = dbx AFS2 手册成对标注
   `>110dB A-weighted, >107dB unweighted` [L2/竞品手册]),**建议 DEC-0022 按此修订** ——
   ⛔ **该修订尚未发生** ⇒ 本表按现行 DEC-0022(A 计权)编,并把"两个都标"列为待裁项 P-1
```

### 1.2 信噪比 >102 dB —— 缺【计权维】,**而且它可能与动态范围是同一个测量**

> ⭐ **一手标准原文**(`AES17-1998 (r2004)` §9.3,我已用 pdftotext 从 PDF 取出逐字):
> > **"9.3 Signal-to-noise ratio or noise in the presence of signal … The test signal for the
> > measurement shall be a 997-Hz sine wave producing – 60 dB FS at the output of the EUT.
> > Any 997-Hz test signal present in the output shall be removed by means of a standard notch
> > filter. The remaining noise shall be filtered with the standard weighting filter."**

```
⭐⭐ 也就是说:业界(以及本仓上游模板 AUD-003)叫「**动态范围 AES17**」的那个 −60 dBFS 方法,
   **在 AES17 自己的条文里叫「信噪比 / 有信号时的噪声」,标准里根本没有 "dynamic range" 这一条。**
⇒ ⇒ 而 PRD 把「动态范围 106」与「信噪比 102」并列成**两个指标** ⇒ 若两者都按 AES17 §9.3 测,
   **它们是同一个测量,不可能差 4 dB** ⇒ 必有一维没写出来
```
**⇒ 最可能的读法(⚠ [L3/推断],⛔ 不是结论,须 CTO 定)**:
```
106 dB = **A 计权**,102 dB = **未计权**,二者是同一底层量的两种计权
  佐证:架构侧实测 A vs 未计权换算 **2–3 dB**(与 dbx AFS2 手册自带的成对数吻合)
  ⚠ 而 106 − 102 = **4 dB**,比 2–3 dB 略大 ⇒ 该读法**不完全对得上** ⇒ ⛔ 不得当成已定
另一种读法:102 = 空闲通道噪声(AES17 §9.1,无信号),106 = 有信号时(§9.3)
  ⚠ 但那样 **SNR 应当【优于】DR**(空闲无失真分量),而 PRD 是反的 ⇒ 该读法与数不符
```
**⇒ ∴ 要 CTO 答一句**:`>102 dB` 是①未计权的同一量,还是②另一个量(空闲噪声)?
**⛔ 在他答之前,信噪比这一行的判据栏只能写 [L4/口径未定],不得填数。**

⚠ **而 AES17 的计权是 ITU-R BS.468-4,不是 A 计权** —— 一手原文 §4.2.3:
> **"The standard weighting filter for all weighted noise measurements should conform to ITU-R BS 468-4 …
> If a standard weighting filter differing from this recommendation is used for a measurement according
> to this standard, **the filter network — and gain if appropriate — shall be specified.**"**
```
⇒ ∴ 「按 AES17 测得 >106 dB(A)」这句话在**字面上不自洽**,除非按上面末句**显式声明偏离**
⇒ 验收表的写法(已按此定):**「程序按 AES17 §9.3,计权按 A(依 §4.2.3 末句声明偏离 BS.468-4)」**
⇒ ⭐ 这不是咬文嚼字:BS.468 与 A 计权在宽带噪声上读数差约一个位数级的 dB,
   报告里不写清楚,同一台机器能报出两个都"合规"的数
```

### 1.3 频率响应 ±0.3 dB —— 缺【处理状态维】与【路径维】

```
PRD 只写「20Hz–20kHz ±0.3dB」,⛔ 没写:
  ① 相对哪个频率(AES17 §7 有规范答案:**"relative to the amplitude at 997 Hz"** [一手原文])
  ② **在什么处理状态下**:全 DSP bypass?EQ 平直但链路在?出厂默认预设?
     ⇒ 而本机输出链含**分频器与 FIR** ⇒ 分频一开,±0.3 dB 在分频点附近**物理上不可能**
  ③ **哪条路径**:1 进 1 出?还是 8×8 满配某一条?(与 1.1 同族:矩阵是求和)
⇒ ∴ ±0.3 dB 只能是**某个明确定义的旁路/平直状态**下的指标 ⇒ 该状态须写进规格,否则不可验收
```

### 1.4 延迟 —— **已定案,而验收表必须两行**(DEC-0021,2026-08-04 CTO 拍板)

```
口径 1(对外规格)= **流水线延迟**(块 I/O + 转换器 + FIR),⛔ 不含用户配置的 IIR 群延迟
口径 2(内部预算)= **群延迟,评价频带下沿 150 Hz** ⇒ 参考配置全链 8.118 ms,余量 3.882 ms
⚠ DEC-0021 风险声明②原文:**两条口径并存 ⇒ 对外文案必须同时给出两个数并标明各自口径,
  否则是新的一名多量**
⚠ 且 DEC-0021 风险声明①:被排除的 **20–150 Hz** 内,参考配置群延迟最大 **21.741 ms**
  ⇒ 「我们同意不管的那一段」有多糟,已在册 ⇒ **验收表必须把它作为一行显式测量并记录**,
    ⛔ 不得因为"不在规格内"就不测 —— 不测就没人知道它有没有变坏
```

## §4 判据的双极值代入自查(lead 纪律③)

> 每条代入"真该过"与"真该不过"各一次,两次答案必须相反。

| 判据 | 真该过 ⇒ | 真该不过 ⇒ | 相反? |
|---|---|---|---|
| **A-2 分档**:每个 N 档各自比对应限值 | 8 路实测 94.5,限值(8 路档)93.0 ⇒ **过** | 8 路实测 94.5 却拿去比 **1 路档限值 102** ⇒ **不过** | ✅ |
| ⚠ **反例(错的写法)**:只报一个 DR 与 106 比 | 1 路实测 102.7 ⇒ 判"接近达标" | **8 路实测 93.9 也会被同一行报成"动态范围"** ⇒ 该写法在真有问题时**照样出一个像样的数** | ⛔ **恒不报警 ⇒ 不是判据** |
| **A-1 状态维**:测量前须声明处理状态 | bypass 态实测 ±0.2 ⇒ **过** | 分频开启态实测 ±6(分频点)⇒ **不过**,且**不得改判为"不适用"** | ✅ |
| **B 组两行**:B-1 与 B-2 必须同时有数 | 两行都有 ⇒ **过** | 只报 B-1(对外口径,数更漂亮)⇒ **不过**(DEC-0021 风险②) | ✅ |
| **B-3 记录行**:不判过不过,但**必须有数** | 有数(哪怕 21.7 ms)⇒ **过** | 缺测 ⇒ **不过**(缺测 ≠ 通过) | ✅ |
| **A-3 口径闸**:口径未定则**不得出数** | CTO 定了口径 ⇒ 可测 ⇒ **过** | 未定口径就先测一个数填进去 ⇒ **不过,中止** | ✅ |
| **C-7 OTA**:断电矩阵每个阶段都要有一次 | 各阶段均试过且可恢复 ⇒ **过** | 只试"下载中断电"这一个最容易的阶段 ⇒ **不过** | ✅ |
| **L 级闸**:进宣传/合同的行必须 L1 | 仪器实测 ⇒ L1 ⇒ **过** | 拿 datasheet 标称或宿主仿真数充数 ⇒ **不过**(C3/C9 BLOCKER) | ✅ |

**⇒ 「这个检查失败时会阻止什么?」**
```
A-2 分档闸 阻止:把 1 进 1 出的数写成产品规格(用户正常用法差 8.74 dB)
A-1 状态闸 阻止:在最有利的处理状态下测,却当成通用规格
B 双行闸   阻止:只报好看的那条口径 ⇒ 制造新的一名多量
A-3 口径闸 阻止:在口径未定时先出数 —— 那个数以后没人能解释它测的是什么
L 级闸     阻止:L4/L2 混进不可逆承诺
```
