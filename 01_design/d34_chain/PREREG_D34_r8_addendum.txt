  「HPF 3.396 ms 是把高通设在 51.5 Hz 时的峰值」
  「PEQ×8 3.771 是 8 段【全部】压在 61.7 Hz 高 Q 时的峰值」
**⇒ 两条与 `d34_analysis.py:446-452` 的实际配置都不符。盘面是:**
```
HPF   = bw_hp(80.0, 0.7071)                     ⇒ fc = 80 Hz(= 我的出厂默认),不是 51.5
        51.5 Hz 是它群延迟曲线的【峰值出现频率】,不是【fc 设置】
PEQ×8 = (63,1.4,+4) (160,1.4,−5) (400,2.0,+3) (1000,1.0,−4)
        (2500,1.4,+5) (4000,2.0,−3) (8000,1.0,+4) (12500,0.7,−6)
        ⇒ 频点跨 63 Hz–12.5 kHz【已分散】,Q ∈ [0.7, 2.0]【中等】,增益 ±3–6 dB
        61.7 Hz 同样是【峰值出现频率】(由 63 Hz 那一段主导),不是「8 段都压在 61.7」
```
**⇒ 即:我上轮给的已经是【分散、中等 Q】的配置,不是最坏设置。**
**⇒ 但 lead 的诉求仍然成立**,因为我确实犯了两个错:

  ② 我**没有同时给最坏可配置** ⇒ 读者无从判断我给的那组处在量程的哪个位置。
⇒ 本轮补这两件。**⇒ 预测方向也因此要说清:参考配置的和【未必】比上轮小很多。**

§1  「参考配置(REF)」的定义与理由 —— 我定,并给出处
--------------------------------------------------------------------------------
⚠ **一条会改变「典型」定义的 PRD 事实**:
  PRD §五.2 明文「**开机自动扫描房间频响,一键自动修正房间驻波**」
  ⇒ **低频窄 Q 陷波不是"用户不会配出来的极端",是本产品的功能会【自动】配出来的。**
  ⇒ 故 REF **必须包含** 2 段低频窄 Q 陷波,否则 REF 不代表真实部署。

REF(逐项及依据):
  HPF        BW12 @ 80 Hz                     [= 我的出厂默认,D3D4 §3③]
  输入 PEQ×8 **启用 4 段**,其余 bypass(默认关):
     45 Hz  Q=8  −6 dB   ← 房间轴向模式(PRD §五.2 自动生成)[L3/房间声学]
     72 Hz  Q=6  −5 dB   ← 同上
     250 Hz Q=1.4 −4 dB  ← 浑浊修正        [L3/工程惯例]
     3.15k  Q=1.0 +3 dB  ← 清晰度提升      [L3/工程惯例]
  输出 PEQ×10 **启用 5 段**(上列 4 段 + 8 kHz Q=0.7 −3 dB)
  分频       LR4 @ 80 Hz                     [= 我的出厂默认 24 dB/oct]
  FIR        关                              [= 我的出厂默认]
  lookahead  1 ms                            [= 我的出厂默认;架构侧已判否降 0]
  房间模式频率依据:轴向模式 f = c/(2L),L = 5–10 m ⇒ 最低 17–34 Hz,前几阶 34–103 Hz
                    ⇒ 45 / 72 Hz 落在小会议室的前几阶内 [L3/解析]

§2  「最坏可配置(WORST)」的定义 —— 参数量程内可配出的最大
--------------------------------------------------------------------------------
  HPF        LR24(4 阶)@ fc 量程下限 20 Hz
  输入 PEQ×8  8 段全部 f = 20 Hz、Q = 50、增益取使群延迟更大的一侧
  输出 PEQ×10 10 段同上
  分频       LR8 @ fc 量程下限 20 Hz
  FIR        512 tap(候选上限)
  lookahead  2 ms(量程上限)
⇒ 用途:**只用于定运行时校验的拦截线**,⛔ 不用于编预算。

§3  预期 / 证伪条件
--------------------------------------------------------------------------------
EXP-9a  REF 与 WORST 必须分开报,且 WORST ≫ REF。
  预期    : WORST / REF ≥ 10×(量级未知,不预设具体值)。
  证伪条件: WORST / REF < 3× ⇒ 「参数量程内可配出灾难性配置」不成立
            ⇒ 运行时校验的必要性论证要重做。

EXP-9b  REF 是否比我上轮那组小。
  预期    : REF 的 D3 PEQ×8 项 **小于** 上轮的 3.771 ms(启用段数 8→4);
            但 REF 的**整体和未必**小很多,因为低频窄 Q 陷波(PRD §五.2)会顶上来。
  证伪条件: REF 的 PEQ×8 项 **大于** 上轮的 3.771 ms ⇒ 「减少启用段数会降群延迟」不成立,
            须查原因(可能是窄 Q 主导),并如实改写 §1 的理由。

EXP-9c  ⭐ 拒绝率的定量代理:从 REF 出发,还能再加几段低频窄 Q 陷波才撞 12 ms。
  做法    : 在 REF 基础上逐段追加「45–120 Hz、Q=8、−6 dB」的陷波,
            每加一段算一次全链合计(按 lead 已裁定的**求和**口径),直到超 12 ms。
  预期    : 能追加的段数 N ≥ 2(否则用户日常调音会频繁撞拒绝)。
  证伪条件: **N = 0**(即 REF 本身已超或加一段就超)
            ⇒ 「按 REF 编预算 + 运行时拦最坏」这个方案**不可用**,须回头改架构(降分频档/关 FIR)。
  ⚠ 本项是**定性判断的定量代理**,⛔ 不等于真实拒绝率(那需要真实用户操作分布,本项目没有)。

EXP-9d  两轨:群延迟仍按 EXP-4 立的两轨(逐节 group_delay 求和 vs 相位差分)核。
  证伪条件: 两轨差 > 0.05 样本 ⇒ 数值不可信,结论不得报出。
