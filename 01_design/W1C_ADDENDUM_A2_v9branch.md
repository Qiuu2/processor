### 2.2 ⛔ 赋值必须**可判定**,不能靠人记得(= 触发器,不是条文)

**做法:把分支从【实际在用的数据类型】里推出来,而不是手打一个字符串。**

```c
/* 每个旁链内核用一个 typedef 声明其旁链数据元素类型,
   且【它的数组必须用该 typedef 声明】—— 改了类型就必须改 typedef,标签随之改 */
typedef float   t3_sc_elem_t;      /* T3 现状 */
typedef int32_t t2_sc_elem_t;      /* T2 现状 */
static t3_sc_elem_t t3_M_l1[T3_M_BINS];        /* ← 由 typedef 声明,不是裸 float */

/* C89 安全的浮点判别:整数除法 1/2 == 0,浮点 1.0/2.0 == 0.5
   ⛔ 不用 sizeof —— sizeof(float) == sizeof(int32_t) == 4,分不开
   ⛔ 不用 C11 _Generic —— CCES SHARC 编译器的 C 标准级别我无法核实 [L4/待核] */
#define W1C_IS_FLOAT(T)   ( ((T)1 / (T)2) != (T)0 )
#define W1C_V9_DERIVED(T) ( W1C_IS_FLOAT(T) ? "granted" : "rejected" )
```

**⇒ 而只有派生值还不够 —— 还要一个能失败的闸:**
```c
/* 作者写下他【以为】的分支;程序算出【实际】的分支;两者不符即 FAIL */
#define T3_V9_EXPECT  "granted"
/* 运行时:assert(strcmp(T3_V9_EXPECT, W1C_V9_DERIVED(t3_sc_elem_t)) == 0) */
```

### 2.3 两极值代入(⭐ 含第三次代入 —— 按我上一轮立的「相反还不够,得看是哪两个方向」)

```
真该过     T3 仍是 float:EXPECT="granted",DERIVED="granted" ⇒ 相符 ⇒ **过**,该行标 granted
真该不过①  有人把 T3 移植成定点、而忘了改 EXPECT:
           EXPECT="granted",DERIVED="rejected" ⇒ 不符 ⇒ **FAIL**   ✓ 与①相反
⭐ 真该不过② 有人把 EXPECT 改成 "rejected" 让它"看起来合规",而**代码仍是 float**:
           EXPECT="rejected",DERIVED="granted" ⇒ 不符 ⇒ **FAIL**
   ⇒ 为什么这一侧也必须能失败:那是「**改标签而不改代码**」的方向 ——
     即"让一个不合规的数看起来合规"。若判据只查"EXPECT 是不是 rejected",这一格会静默通过
   ⇒ ∴ 判据必须是**双向比对 EXPECT vs DERIVED**,⛔ 不得只查其中任一个
```

### 2.4 ⚠ 我给自己留的一处不确定(⛔ 不补齐)

```
T1b 判 `N/A` 依赖一个推断:「AEC 抽取器在音频路,不属 V-9 管辖的检测旁链」
⇒ 依据是 PROVENANCE 引 W1A §4.7(3):AEC 抽取器 ~101 tap,**与 AFC 旁链那只 72-tap 不同、不可复用**
⇒ ⚠ 而我**没有**找到一句明文说"AEC 抽取器的数制由音频路四规格管"
⇒ ∴ 标 **[L3/推断]**,并写进待核:**归架构侧一句话确认**
⇒ 若确认结果是"AEC 抽取器也在 V-9 管辖内",则 T1b 的 N/A 要改 rejected(它是定点)
  —— 而那会让"V-9 敏感内核"从 2 个变 3 个
```

## §3 ⛔⛔ 而我要指出这个设计**自己的**盲区(自审,不等 critic 提)

```
V9_BRANCH 是一个【标签】。而标签**不阻止任何事**。
⇒ 自查那一句:「这个检查失败时,会阻止什么?」
   V9CHK(2.2 的比对闸)⇒ 阻止「标签与代码不符」 ✅ 它是检查
   V9 列本身        ⇒ **什么也不阻止** ⛔ 它是输出
⇒ ⇒ ∴ 只加这一列,我就复刻了自己在 B-2 抓到的那个缺陷
     ——「判定与它作废的数据分离」,只不过这次判定还没发生
```
**⇒ ∴ 这一列必须与它的【消费动作】一起交付,否则它是装饰品:**
```
⭐ 消费动作(⛔ 不在我的件里,须写进 V-9 裁决的处置流程,归 lead 路由):
   **V-9 裁决落盘的同一个动作里,必须包含:**
     ① 对全部已产出的 CSV 逐行扫 V9 列
     ② 凡 V9 == 落败的那一侧 ⇒ 整行标 `VOID_BY_V9`,并在台账记一行
     ③ 凡引用过那些行的下游件 ⇒ 按铁律五反扫
⇒ 而 ③ 现在就可以预先列出来:D13 算力表 / adaptive-dsp 20k cyc/槽 包络 / 架构侧预算
⇒ ⚠ 若这三步没有 owner ⇒ V9 列就只是让我们**事后知道自己错在哪**,而不是**当场停下**
```

**⇒ 第二个盲区(已知限制,不修)**:
```
V9_BRANCH 是**每内核一个二值标签**,而现实可能是**部分受影响**
  例:块浮点 FFT = 整数尾数 + 单独的指数处理 ⇒ 它既不纯粹是 granted 也不纯粹是 rejected
⇒ ∴ 二值标签对块浮点形态**分辨力不足** ⇒ 登记为已知限制
⇒ ⛔ 不现在扩成三值/四值:V-9 未裁,扩了也是押一侧(与 lead 不排 T3 新件同一个理由)
```

## §4 ⛔ 跨档禁止推断条款(lead 点名要写死)

> **T1 档与 T2 档拿到的数,⛔ 不构成 T3 档的任何推断。**

```
理由(⛔ 不是保守,是 DEC-0009 自己的口径):
  DEC-0009 的分档制 = **按模块分档**(T1 规整短环 / T2 FFT 块变换 / T3 控制逻辑),
  各自建立口径与 L 标 —— 分档的**目的**就是禁止跨结构套用
  ⇒ `CLAUDE.md §0` 已有一次实证:8.51 属**单 MAC 短环异结构**,
    套用到 biquad 深链「**正是 DEC-0009 自己禁止的跨结构套用**」⇒ 该套用已被撤回
⇒ ∴ 具体到本轮:
  ⛔ 不得由 T1b(定点抽取,规整短环)推 T3(分支密集、算术强度低的控制逻辑)
  ⛔ 不得由 T2(定点 FFT,规整块变换)推 T3
  ⛔ 更不得由"T1/T2 两档都拿到了定点数"推出"定点锚点问题已解决"
     —— **三档里有一档没有,那件事就没解决**
⇒ ✅ 可以说的:「T1 档与 T2 档已有定点锚点;**T3 档没有,且无件在排**」
```
