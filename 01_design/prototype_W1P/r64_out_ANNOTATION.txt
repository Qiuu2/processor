════════════════════════════════════════════════════════════════════════
**T60=0.2 层(n=3,全部在 T_OBS=12 s 收敛,同一工作点、同一次跑)**:
```
ΔMSG_上界@带限8k_神谕选点_[L2]      逐条 6.0 / 6.0 / 7.5   范围 [6.00, 7.50]  中位 6.00
ΔMSG_实测@带限8k_NHS自选_有duck_[L2] 逐条 1.5 / 2.5 / 1.5   范围 [1.50, 2.50]  中位 1.50
                                    ⇒ **缺口 中位 4.5 dB**
```
> **⇒「选点方式」这一维,本轮实测缺口 4.5 dB(T60=0.2 层中位),比派单表里的 4.0 更大。**
> **⇒ 与「房间混响 T60 差 2.5 倍 ⇒ 1.67 dB」相比,仍是【算法自己的选择】主导,不是房间。**

>   **⛔ 不得报成"缺口 4.5 dB"这样一个跨层的数。**

**⚠ 与旧数的类别对账(B-3 纪律)**:
| 数 | 是什么 | 不是什么 |
|---|---|---|
| 5.67 / 3.50–7.50(r57) | **上界**,神谕选点,`T_OBS=6s` 固定窗 | 不是 NHS 性能 |

⇒ 三者**不是同一个量**,不得互相替换,也不得说"从 5.67 掉到 1.50"——它们量的类别不同。

三、⭐⭐ 唯一那条 ≥4 dB 是【兜底冒名顶替】—— F33 的第三次,而且是最干净的一次
════════════════════════════════════════════════════════════════════════
`T60=0.5 / seed=1 @ T_OBS=48 s`(未收敛条,按 A-3 计入的那条):
```
ΔMSG_自选@有duck  4.00 dB   ← 唯一一条 ≥4
ΔMSG_自选@消融    1.00 dB   ← 扣掉宽带兜底后,陷波机制只值 1.00
duck 贡献         3.00 dB   ← **75% 来自把音量拧小 6 dB**
实测 f_trig(该档) 22.0 Hz   ← **低于 f_det_lo = 120 Hz ⇒ NHS 结构上看不见它**
NHS 实际挂的 5 个陷波 @[1033.8, 2517.3, 4051.3, 5502.8, 7580.3] Hz
                          ← **没有一个在 22 Hz 附近;它陷的全是别的频点**
```
> **⇒ 那 4.00 dB 的构成是:算法看不见真正的啸叫点,陷了 5 个别的频点,**
> **然后靠宽带兜底把整体拧小 6 dB —— 而报表上它是「达标的那一条」。**
> **⇒ 这正是 §7.1③ 记的失效形态:【静默 + 自我肯定】。本轮第一次在【达标判定】上抓到它。**
⇒ **处置:该条不得计入达标。** 主统计(0/3)本就没算它;A-3 的第二统计里它是唯一的 1,
  **本件把它逐项拆开,读者不必相信我的结论,自己看 `duck 贡献 3.00` 与 `f_trig 22.0` 两列即可。**

**duck 贡献六条**:`0.00 / 0.50 / 0.00 / 0.00 / 3.00 / 0.00`
⇒ **「f_cut=8k 下 duck 贡献 0.00」不成立**(r62 亦为 4/6 非零);
  它**大多数时候是 0,但在唯一一条达标行上是 3.00** —— **均值会把这件事抹掉,故逐条报。**

四、T60=0.5 三条【全部未在 48 s 内收敛】—— 这本身是结果,不是失败
════════════════════════════════════════════════════════════════════════
逐条 `ΔMSG_自选@有duck` 随 T_OBS 的轨迹:
```
0.5/sd0  (6, 3.0) (12, 2.5) (24, 2.0) (48, 2.5)      f_min = 52.0 Hz
0.5/sd1  (6, 4.0) (12, 1.0) (24, 0.5) (48, 4.0)      f_min = 22.0 Hz   ← 摆幅 3.5 dB
0.5/sd2  (6, 3.5) (12, 2.0) (24, 2.0) (48, 2.5)      f_min = 170.0 Hz
对照 T60=0.2 三条:(6,1.5)(12,1.5) / (6,2.5)(12,2.5) / (6,1.5)(12,1.5)  ← 一档即稳
```
**成因(直接观测,非推断)**:`0.5/sd1` 的臂 N `f_trig` 逐档为 **7580 → 7580 → 1034 → 22.0 Hz**
⇒ **每加长一档,"赢家"换到一个不同的临界点、而不同频点的建立时间差一个量级**
⇒ ΔMSG 不是在收敛,是在**换被测对象**。
> **⇒ F36 的 1/f 规则是【必要不充分】的**:`0.5/sd2` 的 `f_min=170 Hz` 使 C1 从第一档就 ✓,
> **它照样没收敛** ⇒ 自适应臂还有**第二个时间尺度**(NHS 自己的检测→分配→加深),
> 而 F36 只管住了第一个。**这一条是本轮对 F36 的实测补强(预注册修订 A-2 已事先写出方向)。**

**⛔ 阶梯为什么不能再往上加**:`T_MAX = 48 s` 受 `nhs.py:94 lift_after_s = 60 s` 硬限 ——
超过 60 s 臂 O 的预挂槽会进入 LIFT ⇒ **被测对象在窗内自己变了**。
⇒ **要测更长的窗,必须先决定:①放弃臂 O,或 ②改 `lift_after_s`(= 改被测算法)。
  这是设计取舍,归 lead / 架构侧,我不自决。**
