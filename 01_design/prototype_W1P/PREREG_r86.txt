1. 机制 A(抢占抖动)要求什么
═══════════════════════════════════════════════════════════════════
**实测根因(r85)**:被抢走的槽 `depth_old` 中位 **−0.96 dB** ⇒ 刚挂上就被抢。
**代码根因(读码)**:新分配的槽 `has_affirmative_verdict = False`(nhs.py 新占用处),
而抢占的候选集正是 `[s for s in slots if not s.has_affirmative_verdict]`
⇒ **新生槽【出生即可被抢】。**
```
⇒ 我的推导:该标志把两个不同状态**合并**了 ——
     ① 「尚未判决」(探针还没来得及给结论)   ← 新生槽
     ② 「已判决且无肯定结论」(探针判了,没证据)← 真该让位的
   ⇒ **抢占把 ① 当成 ② 处理** ⇒ 于是新生槽在满槽期被反复清零
⇒ 机制 A 要求:**抢占的排序须能区分「尚未判决」与「已判决且无肯定结论」**,
   前者受保护,后者才是可抢的
```
**⇒ 与 lead 的读法对照**:
```
lead:「抢占不该抢走一个还没压到某个最小深度的槽」
我  :「抢占不该抢走一个【还没被判决过】的槽」
⇒ **相同**:都要求给新生槽一段保护期
⇒ **不同**:lead 用【深度】作保护判据,我用【是否已判决】
   ⚠ 而我认为这个差别重要:深度是一个**新阈值**(又一个"拍的数",与 T_low/R_RISE/C-8b 同族);
     而"是否已判决"是**已有的状态**,不引入任何新阈值 —— 与 F55 当初赞许 prefer_unnotched 的
     理由同型(只是那次方向猜错了)。
   ⛔ 但我不据此说我的更好:**两者都未验**,而上一个"不引入新阈值"的修法正是被证伪的那个。
```

2. 机制 B(复检被挤出)要求什么
═══════════════════════════════════════════════════════════════════
**实测(r85/r84)**:零抢占的两条种子上,修法开 ⇒ 被截断挡掉的**已挂陷复检占比升到 100%**,
`A3_deepen_real` 降 16%/13%,深度中位变浅 +1.50/+4.50 dB。
```
⇒ 我的推导:`out[:1]` 是一个**预算**,而预算总是针对某种**资源**。
   它限制的应该是【新分配】—— 因为新分配消耗**槽**(NN=8,真稀缺)。
   而**复检不消耗槽**:它走的是 `same` 分支,只是把已有槽的 target 再压 3 dB。
⇒ ⇒ **这个预算被施加在了一个它不该管的动作上** —— 复检与新分配消耗的是不同资源,
     却在抢同一个名额。
⇒ 机制 B 要求:**名额只应对【消耗槽的动作】计费;复检不占槽,就不该占名额。**
```
**⇒ 与 lead 的读法对照**:
```
lead:「复检与新峰在做两件不同的事(加深 vs 新增),不该抢同一个名额」
我  :同一结论,但给出了**为什么** —— 名额是【槽】这个资源的预算,而复检不消耗槽
⇒ **相同**(结论一致);**不同**在于我给出了判据的依据:**按资源消耗计费**
   ⇒ 这条依据可延伸:PANIC 走 out[:2] 也是同理(它消耗槽,所以计费是对的)
```

3. ⭐⭐ 两条要求【互相冲突】—— 而这就是设计的核心(lead 预判成立)
═══════════════════════════════════════════════════════════════════
```
B 的修法 ⇒ 复检不再占名额 ⇒ **新峰通过截断的流量上升**
A 的病灶 ⇒ 恰恰在【满槽 + 新峰持续到来】时被触发(抢占只在无空槽时发生)
⇒ ⇒ **单独实施 B,会把更多新峰送进那个正在抖动的分配器 ⇒ 放大 A**
⇒ 而单独实施 A(保护新生槽)⇒ 满槽时新峰无处可去 ⇒ `n_blocked` 上升 ⇒ 真啸叫被拒
⇒ **二者不能独立实施** —— 这正是 lead 预判"冲突本身就是设计核心"的那个点
```
**⇒ 由此得到一条【两者都要满足】的形态(⛔ 本轮不实施,只记):**
```
名额按【资源】计费(B)+ 抢占按【判决状态】排序(A)
⇒ 复检自由通过(不占槽) ∧ 新峰竞争槽 ∧ 新生槽在判决前不被抢
⇒ 而槽真不够时,应走 `slots_exhausted` 的兜底路径(它已存在),而不是靠抖动"腾"槽
```
