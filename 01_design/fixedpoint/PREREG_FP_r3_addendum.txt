§1  r2 触发的证伪 → 本轮对【被测物】的改正(不是对判据的改正)
--------------------------------------------------------------------------------
[C-1] CHK-11b 的证伪条件命中:实测累加器占用 **58.005 bit < 63**。
      ⇒ 按 r2 §2 预先写好的要求,改正 `chdsp_fixed.h` §累加器:
        把 (a)【类型范围上界 64.81 bit,构造上不可超越】与
           (b)【本项目参数范围内实测 58.005 bit】**分两行写**,
        并把「禁止降到 int64」的理由从「真实工况会溢出」(已被证伪)
        改为「(b) 是经验扫描、随参数范围放宽而失效,而 SHARC+ 的 80-bit MRF
        按 (a) 要求不花任何代价」。
[C-2] CHK-5f 实测:自由量化在 **251/500** 个 fc 上破坏高通 DC 零点,
      最坏单节 DC 增益 **−59.26 dB @ 20 Hz**;r1 在 fc=80 Hz 得到的精确 0 是巧合。
      ⇒ 新增被测接口 `chdsp_coef_hplp_from_f64()`(只量化 b0,b1=∓2b0、b2=b0),
        把「零点由构造保证」做成接口,而不是留一句注释。
[C-3] CHK-2 / CHK-7 / CHK-11b 三条**退役**(保留在代码与输出里、标注理由、不计入判定):
      CHK-2  —— 无分辨力(r2 CHK-2c 实测种子间 s=1.226e-6 ≫ 判据 1e-7),由 CHK-2b 取代;
      CHK-7  —— 判据窗口 [−110,+24] 是我拍的估计,真实包络下界 = −109.816 dB(CHK-7b);
                ⛔ 不移动标杆,规格改以 CHK-7b 实测包络书写,原判据原样留痕;
      CHK-11b —— 断言内容已被证伪,改正落在被测物上(见 C-1)。
      ⚠ 退役 ≠ 删除:三条的原判据与实测值都留在输出里。

§2  r3 新增:杀伤矩阵(假绿纪律的正面证据)
--------------------------------------------------------------------------------
KILL  做法:新增 `CHDSP_CHECK_FORCE_GOOD_ASSERT=1`,使断言**一律用好版本判据**,
      不再随 BROKEN 宏自适应;然后把这份**同一套好判据**分别跑在三个坏模块上。
      ⚠ 为什么 r1/r2 的做法不够:那时断言随构建翻转,坏版本里 CHK-1 断言的是
        「符号翻转确实发生」并 PASS ——**那不是「检查杀死了变异」,是检查换了题目**。

  预期:
    WRAP  → 至少杀 CHK-1 或 CHK-1n
    TRUNC → 至少杀 CHK-2b 与 CHK-4
    NOEF  → 至少杀 CHK-4
  证伪条件:**任一变异在好判据下全部 CHK 通过(存活)**
            ⇒ 对应的检查不依赖被测物,该检查作废并重新设计。

KILL-N 阴性对照(团队纪律 D6-y 的第二个方向 / C-5「干预确实生效」的镜像):
  好模块 + 好判据(FORCE_GOOD_ASSERT=1,无 BROKEN)必须**零 FAIL**。
  证伪条件:无变异时也出现 FAIL ⇒ 上面的「杀死」不能归因于变异,杀伤矩阵作废。
