## §1 ⛔⛔ 我先复核算法侧的三条,再改方案(⛔ 不照转述改)

### 1.1 (a) **它说我的"内插"是个除法 —— 我算了,它对**

```
我用的两点:  (k=2.0, 7.0–8.2k)  与  (k=8.51, 30–35k)
由端点反推 N_op:  7.0k/2.0 = 3500   ｜  30k/8.51 = 3525
                  8.2k/2.0 = 4100   ｜  35k/8.51 = 4113
⇒ ⭐ **两点落在同一条过原点的射线上** ⇒ 所谓"两点内插"= 解 `N_op·k = 20000`
⇒ 直接除:20000/3500 = 5.714 ｜ 20000/4100 = 4.878
   而我内插得 5.680 / 4.866 —— **同一个数**(差异仅来自端点取整)
```
**⇒ ∴ 那个 ±0.4 **不是**测量不确定度,也不是"越线点估得不准" ——**
**它就是【手算 op 区间 ±8% 的宽度】被一个除法搬了过来。**
**⇒ ⇒ 我把一个**恒等变形**报成了一个**估计**,并给它配了一条精度约束。**

## §2 ⇒ 新做法:**T3 档直接量 `cyc/槽`,与 20k 一步比较**

```
旧:测 cyc/MAC ⇒ 乘 N_op(手算,从未实测)⇒ 与 20k 比      ← 两个估计量的商
新:**直接测 cyc/槽** ⇒ 与 20k 比                          ← 一个数,无乘子,无内插
⇒ ⭐ 而这同时**消掉了 N_op** —— 那正是墙的确切位置(它是手算的、从未实测)
```
**⇒ 而它答了那个一直悬着的问题**:
```
问:「这个数是不是原理上只能估?」
答:⛔ **不是。它可测** —— 只是**测的对象要换**。
⇒ 「W1-C 落在哪一侧」**会**被回答,前提是测 `cyc/槽`,⛔ 不是测 cyc/MAC 再换算
```

### 2.1 ⚠ 而 `cyc/槽` 自己也必须写明取值范围(否则它是新的一名多量)

```
凡报 cyc/槽,必须同报:NT(跟踪轨数,现 12)· M_BINS(现 128)· 通道数 · 槽率(HOP_SC/FS_SC = 16 ms)

⇒ ⛔ 缺任一项 ⇒ 该数不可与 20k 包络比较(包络也须在同一组参数下声明)
```

### 3.1 ⭐⭐ 第三次代入 —— **这次有对象,而且它就是本判据的要害**

```
问:对我方【有利】的那一侧是哪个?⇒ 「实测 < 20,000 ⇒ 合规 ⇒ 什么都不用改」
问:什么会让它**假性偏低**?
⇒ ⛔ **T3 内核不是生产代码** —— 它自己的文件头就写着:
   「⛔ 不追求与 nhs.py 逐行功能等价 —— 没有真实频谱输入、没有真实 IPMP 配对、
     **没有真实 Track 生命周期管理(`_update_tracks`/`_birth`/`_allocate` 均未搬)**」
⇒ ⇒ ∴ 它**系统性少算**生产槽内的工作量 ⇒ 实测值**天然偏低** ⇒ **天然偏向"合规"**
⇒ ⇒ ⇒ 这正是「对我方有利的那一侧没有闸」，第五次出现
```
**⇒ ∴ 判据必须带一道闸,⛔ 否则这条新判据比旧的更危险(它看起来更直接、更可信):**
```
G7 · 覆盖声明闸
断言   报 cyc/槽 时,必须同时给出**两张显式清单**:
       ① 本内核**已建模**的生产函数(现:_imsd / _phpr_veto / _is_dom / _classify 同构)
       ② 本内核**未建模**的(现:_update_tracks / _birth / _allocate / 真实 IPMP 配对 / 真实频谱)
判定措辞 ⛔ 一律写「**合规(仅对①所列子集)**」,⛔ **不得**写「合规」
失败    出现一句不带②清单的「cyc/槽 < 20k ⇒ 合规」⇒ **该结论作废**
两极值  真该过:带两张清单 + 措辞含"仅对子集" ⇒ **过**
        真该不过:报「12,000 < 20,000 ⇒ 合规」⇒ **不过**(它把子集读成了全量) ✓ 相反
它阻止什么 阻止**用一个已知少算的数去宣布合规** —— 而少算的方向正好让人放心
```
⚠ **而 G7 只挡措辞,⛔ 挡不住"少算多少"** —— 那个量要等生产 C 代码存在后才可能补齐。
⇒ ∴ **代表性缺口在这里从"脚注"升为"判据的一部分"**,但它**没有被消除**。

## §5 ⭐ 而我那句「精度不是限制因素」必须**收窄**(lead 点名)

```
原句(A5 §0.5):「本微基准的精度已不是"越线点落在哪一侧"的限制因素」
⇒ 它对**旧问法**成立(旧问法里挡路的是 N_op,不是精度)
⛔ 而对**新问法**必须重判:直接测 cyc/槽 时,**精度可能又变成限制因素**
   —— 若实测落在 20k 附近(例如 18–22k),那么"在不在包络内"就**真的**由测量精度决定
⇒ ∴ 收窄后的正确表述:
   「精度不是**旧问法**(cyc/MAC → 换算 → 越线点)的限制因素;
     而在**新问法**(直接测 cyc/槽 与 20k 比)下,**若实测落在 20k 邻域,精度即是限制因素** ——
     此时 R=8 重复与半宽约束**从"服务锚点区间"升为"服务合规判定"**」
⇒ ⭐ 判别式(可执行):**|实测 − 20000| ≤ 2 × 半宽 ⇒ 判定落入"精度决定区" ⇒ 必须加重复次数**
   ⛔ 而不是事后才想起来问精度够不够
```
**⇒ ⚠ 这一条正是 lead 那句「一条纪律只堵一个方向时,它自己就成了下一个坑」的实例:**
**我上一轮堵了"以为更精就能答",而没堵"以为精度永远不重要" —— 现在补上。**
