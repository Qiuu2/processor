═══ 0. 为什么它排第一(lead 定)
```
其余失效模式问的是**做得好不好**;而 B-2 问的是**能不能做**
⇒ 若判据分不开这两种情形 ⇒ NOM 虚高 ⇒ 全体被压 ⇒ **该功能名不副实**
⇒ ⇒ ∴ 它是唯一一条「若不成立,整件事白做」的
```

═══ 1. 构型(⛔ 两场景的**每通道电平**须相当 —— 否则电平判据是被人为削弱的)
```
S1 **两个人**   :x1 = h1 * s1 , x2 = h2 * s2   (**不同源**,s1 ⟂ s2)
S2 **一人两麦** :x1 = h1 * s  , x2 = h2 * s    (**同源**,不同 RIR ⇒ 不同延时/染色)
h1/h2 = clrig.make_F 的两条独立 RIR(不同 seed);源 = 白噪声(⛔ 无语音素材,仍挂 CTO)
⇒ 每场景各 **12 次试次**(不同 seed)⇒ 给出**分布**,⛔ 不给单点
⚠ 归一化:两场景均把两通道 RMS 对齐到同一值 ⇒ **电平判据在构造上拿不到便宜**
```

═══ 2. 被测的三个量(⛔ 不设阈值,只量分布与是否可分)
```
D_lvl   = |L1 − L2| (dB)         —— **电平判据能拿到的全部信息**
D_env   = 两通道**包络**的最大归一化互相关  —— **便宜**:automixer 本来就有逐通道包络
D_xcorr = 两通道**原始信号**的最大归一化互相关(带 lag 搜索) —— **贵**:需 lag 搜索
⇒ ⭐ 而 D_env 与 D_xcorr 的对比,直接回答 §2 的成本问题:
   **判据需不需要贵到超出「结构性有界」那个界**
```

═══ 3. ⭐ 判据(跑前写死;⛔ 不取阈值,只判**区间是否重叠**)
```
可分性判据(照 r93 那条:判据要从实测分辨力来):
   `sep(D)` := **S1 的取值区间与 S2 的取值区间【不重叠】**(max/min 不交叠)
H1 ✅ **预期**:`sep(D_lvl) = False` ⇒ **电平判据无分辨力**
     ⇒ ⚠ 这是我**预期**的结果 ⇒ 举证门槛更高:若 D_lvl 反而可分,须**先查构型**再下结论
H2 ⭐ **主问**:`sep(D_env)` 与 `sep(D_xcorr)` 各是什么
     ✅ 若 `sep(D_env) = True` ⇒ **便宜的判据够用** ⇒ §2 的界不受威胁
     ⚠ 若 `sep(D_env)=False ∧ sep(D_xcorr)=True` ⇒ **能做,但要贵的** ⇒ 须重估 §2
     ⛔ 若两者皆 False ⇒ **本构型下无可用判据** ⇒ **顶格报**:整件事的性质改变
H3 ⭐⭐ **有利侧的闸**(lead 点名):判成"一个"会让 NOM 不虚高 ⇒ **看起来更好**
     ⇒ ∴ **两个方向都必须报**:
        (a) S2 被判为"同源"的比例(⇒ 功能有效性)
        (b) **S1 被误判为"同源"的比例**(⇒ **真的两个人被合并** = 有利侧的危害)
     ⛔ 只报 (a) 不算数
⚠ 量具可表示性自查(r92 那条):三个量均为**连续量**(dB / 相关系数)
   ⇒ 「区间不重叠」是可表示的结果 ⇒ 判据的前提成立
```
