## MAJOR-1 · 三臂豁免的合取前置门「因果时序」在 case (b) 与重生轨上恒假 —— 可达性表宣称的覆盖与规则本体自相矛盾,B-F1 的收口论证不成立

**位置**:§3.2 豁免式(:314-332)、可达性表 case (b) 行(:353)、case (b) 缓解②③与"诚实注"(:371-372)、§1.2-C(:140)、§5.5 `StandbyShadow`(:577-580)、§10.3 D1 扫描表(:897-913)、§3.5-#11 残余栏(:406)。

**事实(逐条可核)**

1. §3.2 的豁免规则是**三重合取**:
   `豁免否决 ⟺ f 是族内最大成员 ∧ 因果时序(t_veto_start 晚于 t_onset ≥2 槽) ∧ (臂1 ∨ 臂2 ∨ 臂3)`
   即"因果时序"是**所有三臂共用的前置门**,不是臂1/臂2 专属。§1.2-C 对 relaxed_entry 轨复述同一约束("PHPR 豁免仍须因果时序")。
2. 可达性表 case (b) 行原文:「臂1/臂2 不可达,**因果时序失效(PHPR 条件自诞生即真)**→ **臂3 为唯一豁免臂**」,判定栏写「有臂3:PERSIST ≈P_persist」。
   —— **前半句承认因果时序为假,后半句仍宣称臂3 可达**。按第 1 条的合取式,因果时序假 ⇒ 整个豁免式为假 ⇒ 臂3 命中也不产生豁免 ⇒ PHPR 否决成立 ⇒ PERSIST 被否 ⇒ **case (b) 在有 GR 遥测时同样不可分类**。
3. 同一矛盾在 case (b) 触发源 4/5 的"诚实注"(:372)重复一次:「第四/五种中**臂3 均可达**(限幅器持续出力,GR active)」——同样只核了臂3 自身条件,未核合取门。
4. **影子继承把这条洞焊死**:§3.2 缓解② / §5.5 `StandbyShadow` 继承 `{f, t_removed, rapid_onset, t_veto_start, persist_credit}`,**不含 t_onset/t_born**。重生轨 `t_born = now`,而继承来的 `t_veto_start` 是**旧的、更早的**时刻 ⇒ `t_veto_start < t_onset` ⇒ 因果时序**结构性为假**。设计用来救 case (b) 源4 的机制,**恰好使被救的轨永久拿不到豁免**。
5. **§10.3 的 D1 扫描表漏掉了这一层**:表内扫了 T_low / PAPR / PNPR / TRACKED 连续性 / PERSIST 连续 / 老化 / T_panic / 臂2 R_RISE / 臂1 s_max / 臂3 `GR valid ∧ active≥N_gr` / 轨表容量 —— 但**没有扫**豁免式上的另外两个合取门:「**因果时序 ≥2 槽**」与「**f 是族内最大成员**」,以及臂3 自带的「**f 为该通道高位窄带主导峰**」(该谓词全文未定义,且在掩蔽场景下按 CHECK F-2 的构造恰恰为假)。D1 纪律的立法原句是"豁免条件在目标场景恒 False = 写了等于没写",本轮**漏扫的恰是豁免式本身的合取门**。

**为什么是问题**

- v1.0 verdict 的 B-F1 明令:不得只靠放宽豁免条件交差。v1.2 确实做了远超"放宽条件"的工作,但**收口那一步的可达性论证是错的**:表格给出的是"某一臂可命中",而规则要求的是"合取全真"。
- 后果是 §3.5-#11 与 §9-⑦ **定稿的残余盲区表述比真实盲区窄**:定稿写的是「无轨迹历史 ∧ 遥测降级 ∨ tap < T_low_gr」,而按规则本体,**case (b) 的盲区与遥测是否降级无关**——只要"诞生即平台",三臂全被合取门挡住。这条表述已被 IF-v1.4 C11-④ 与 W1-A §4.1-④ 两侧引用为定稿,错误会同步扩散到两份承重文档与 V-12 用例设计。
- 这是 B-F1 原病型的**第二次复现**(用一个在目标场景里为假的条件去关一条路),而作者本人在 §8.3-6 里刚刚以同一逻辑向合同侧提了异议。**同一把尺子没有量到自己的豁免式上。**

**修法方向(不写实现)**

- 先裁定意图:因果时序到底是"谐波成因证据"(则应只约束臂1/臂2,臂3 的 GR 事实本身就是另一类成因证据)还是"全局硬门"。二选一后,**规则本体与可达性表必须同源改**,不能只改表。

## MAJOR-2 · case (c1)「钉住啸叫伴交谈」的覆盖论证不成立:老化门未改 + T_exempt=10s 低于典型发言时长,三条宣称机制中两条不参与桥接

**位置**:§3.3 PERSIST 驻留语义(:382-384)、§1.2 IPMP 老化(:129)、§1.2-D 三态(:147-156)、§3.2 缓解②③(:371)与 T_exempt(:321)、§3.2 case (c1)(:354)、§10.3 D1「老化 6 槽」行(:909)、§7.2-B10(:738)。

**事实**

1. §3.3 把 PERSIST 由严格连续改为滑窗命中率,理由写的是:「严格连续下,一段 1-3s 的讲话就会**触发老化删轨** ⇒ PERSIST 计时永远重置」。
2. 但**老化规则本身没改**:§1.2 仍是「连续 6 个**可观测且未命中**的槽 → 删轨」= 96ms@B3。
3. 讲话期的槽是**已交付**的,而啸叫被 GR 压下 + 被语音掩蔽(作者自己的 CHECK F-2 证明掩蔽下全带 PAPR 塌陷)⇒ 按 §1.2-D 的三态定义,这些槽落入「**未命中**」而非「未观测」⇒ **正常计老化**。
   ⇒ **改 PERSIST 的驻留语义完全不触及删轨路径**:1-3s 讲话仍在 96ms 内删轨。滑窗命中率(容忍 30% 未命中)在"连续未命中 ≥6"面前**结构性用不上**——能被容忍的未命中长度上限被上游老化门钳死在 5 槽。
4. §10.3 D1 表已识别该门(「老化 6 槽 | **是**(讲话段 1-3s ≫ 6 槽)」),但填的处置是「**按可观测槽计** + 影子继承」——**"按可观测槽计"对本场景无效**(讲话期是未命中不是未观测)。这是 D1 纪律警告的"洞只是搬了个位置"在同一张表里发生。
5. 于是桥接讲话段的唯一机制是**影子继承**,而其保鲜期 `T_exempt = 10s`(§3.2 :321,亦用于缓解②③ 的继承条件)。**会议里单人发言轮次通常 10s–数分钟**,远超 10s ⇒ 影子过期 ⇒ 重生轨零历史零信用,退回 case (b)「诞生即平台」⇒ 再叠加 MAJOR-1 的合取门 ⇒ **不可分类**。
6. 连带:§7.2-B10 的预期写「完整版必须 PASS」。按上述推理,完整版在"讲话段 > ~10s"的 (c1) 变体上**同样会 FAIL**——这是一条现在就能证伪的预测,若照此设计 B10 用例,测试结果会与文档预期相反。

**为什么是问题**

这正是 D2 纪律点名的最坏一类:**故障触发条件与故障模式正相关**——发言越长、房间越活跃,桥接越失效,而那恰是钉住啸叫最该被抓住的时刻。且 §3.3 给出的因果解释("改连续性语义即可跨过讲话段")是**错的因果**,错的理由会让下游停止检查老化路径——这句话是作者自己在 §8.3-6 写的。

**修法方向**

- 把"删轨"与"PERSIST 计信用"解耦:讲话段要么不删轨(老化门也按同一豁免/GR 条件放宽),要么删轨但让继承窗覆盖真实发言轮次时长(T_exempt 需按"最长单人发言轮次"量级定,且**该量级是可从会议语料统计的,不是纯 [L4] 拍值**)。
- 无论选哪条,§3.3 的因果叙述必须改写为真实机制,§10.3 老化行的处置栏同步改。
- §7.2-B10 的"完整版必须 PASS"须给出讲话段时长的适用域,否则该 broken 版会变成一条误导性验收判据。
