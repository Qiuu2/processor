# 一、BLOCKER

## ⛔ BLOCKER-1 · CHK-10 负向编译测试是假绿:它的 PASS 判据是"编译失败",不是"被类型层挡住"

**位置**:`fixedpoint/check_negcompile.sh:15-22`(`expect_fail`);判据被 `PREREG_FP_r1.txt:105` 原样写死
(「证伪条件: 任一片段**编译通过**」);结论进 `D34_FIXEDPOINT_CONVENTION_v0.1.md` §8.2 表与 §13。

**问题**:`expect_fail` 只问 `$CC -c` 是否返回非 0。**任何**编译错误都算 PASS ——
包括"这个测试要测的接口已经不存在了"。

**我的实证(两条,都在拷贝目录上做,原件未动)**:

```
实证 A ── 把 chdsp_apply_gain 从头文件改名为 chdsp_apply_gain_v2(⛔ 不动任何类型定义)
          ⇒ N4(「dB 当线性增益用」——文档自称"本项目最贵的一类量纲错")现在什么也没测
          ⇒ CHK-10 输出:PASS=8 FAIL=0     ← 一个字都没变

实证 B ── 把 chdsp_fixed.h 整个拿走(被测物完全消失)
          ⇒ N1–N5 仍然 5/5 PASS(理由是 "fatal error: chdsp_fixed.h: 没有那个文件")
          ⇒ 只有 P1–P3 翻红
```

**⇒ 这正是本项目治理 §5 的红线原句**:「验证器在占位/恒等/旧文件上照样 PASS = 假绿,比没验更危险」;
也是 **D6-d**「拿掉被测物,这个数应该等于多少?」——答案应是 0/5,实测是 5/5。

**⚠ 必须同时说清的**:**被检查的机制本身是有效的。** 我造了作者没造的那条对照
(同样五个片段,只把 `CHDSP_STRICT_TYPES` 从 1 改成 0):

```
STRICT_TYPES=1 → N1 N2 N3 N4 N5 全部编译失败
STRICT_TYPES=0 → N1 N2 N3 N4 N5 【全部编译通过】⇒ 5/5 翻转
```

**⇒ 所以 §8「量纲混用编译不过」这个结论是真的。假的是它的证明。**

**若不修,下游会怎么错**:
1. `channel-dsp` 将在此头文件上写 D3/D4 的全部模块。头文件会持续演进(加饱和遥测、加模块状态、改函数签名)。
   **CHK-10 会在接口每一次演进后继续报 8/8 PASS,而它测的东西可能早就不在了** ——
   这不是假设,实证 A 就是一次接口改名。
2. 一旦某次改动**真的**打开了量纲缺口(例如为了 ABI 把某个 struct 退回 typedef、或加了一个
   接受 `int32_t` 的便利重载),**唯一本该拦住它的机械护栏会安静地报绿**。
3. 该缺口的下游后果是本项目已经点名的那一类:`dB` 当线性增益用 / 累加器自选移位。
   到那一步才发现,已经是 D3+D4 全部模块都编译过了之后。

**修法(两条都要,任一单独不够)**:
- ① `expect_fail` 增加**诊断内容判据**:错误文本必须命中该片段针对的那一类
  (如 N1/N2/N3 须命中 `incompatible type`/`invalid operands`;N5 须命中对 struct 的 `>>`;
  N4 须命中参数类型不兼容),**⛔ 命中"file not found"/"implicit declaration" 一律判 FAIL**。
- ② 把我做的那条对照**固化进脚本**:同一批片段在 `CHDSP_STRICT_TYPES=0` 下必须**全部编译通过**。
  这是 D6-d 的机械形式,而且它顺带把 §8.3「逃生口」那条声明也变成被检查项。
- ③ 顺带把 `PREREG_FP_r1.txt:105` 的证伪条件在 r4 addendum 里**补一条**(⛔ 不改原件,新增)。

**复核方式**:我给的两条实证命令可原样重跑;修完后实证 A(改名)必须让 N4 翻 FAIL,
实证 B(拿走头文件)必须让 N1–N5 全翻 FAIL,而正常构建仍 8/8。

## MAJOR-2 · §6.4「整条链的噪声底」漏掉级间增益 —— 而该节标题正是 D-4「⛔ 不许只验单级」

**位置**:`D34_FIXEDPOINT_CONVENTION_v0.1.md` §6.4 全表 + §6.3 结论句;
同一模型已传播到 `d34_chain/d34_analysis.py` 的 `EXP-5`(第二件也踩)。

**问题**:模型是 `噪声底 = −173.35 + 10·log₁₀(N)`,即**把 N 个量化噪声源直接功率相加**。
但第 k 节的量化噪声要**经过第 k+1…N 节的传函**才到链末。链内每一级的增益是自由参数,
而 §6.2-4 **明文允许**用户「把 8 段 PEQ 全部 +15 dB 叠在同一频率」。

**我的独立复算**(每节噪声 = q²/12,经其后各节 |H|² 在 0…π 上取均值后求和):

| 配置 | 实算链末噪声 | 与 §6.4 的 −164.32 差 |
|---|---|---|
| ① 8 节全单位增益(文档模型的隐含前提) | **−164.32 dBFS** | +0.00 ✓ 模型在此前提下精确 |
| ② 文档自己 CHK-5 用的那 8 段(+6,−8,+4,−10,+12,−6,+9,−15) | −163.81 | **+0.51** |
| ③ 8 段各 +6 dB 分散(完全现实的一档) | −160.76 | **+3.55** |
| ④ **§6.2-4 明文允许**:8 段全 +15 dB 同频(1 kHz,Q=1.4) | **−91.64 dBFS** | **+72.68** |

**⇒ 配置 ④ 同时突破文档自己的两条对标**:PRD ≤ −106 dBFS(**差 14 dB**)、
作者设计目标 ≤ −120 dBFS(**差 28 dB**)。§6.4 表里写的余量 52.9 dB / 38.9 dB **在该配置下不存在**。

**⚠ 我必须同时说清两件事,免得被读成比实际更严重**:
- 配置 ④ 里信号本身也被抬 +120 dB,链内 24.08 dB 余量会先饱和 ⇒ 它是个**退化工作点**。
  但**噪声是链内产生、被后级放大的**,把输入调小一点也不会降低它 ⇒
  **链末可用动态范围确实真实地少了 72.68 dB**,这不是量的类别错。
- 配置 ②③ 表明:**现实预设下结论方向(算术噪声不是瓶颈)仍然成立**。
  **⇒ 所以要修的是【那个数】和【它的适用范围声明】,不是那个结论。**

**为什么是 MAJOR**:该数承重两处 —— §6.3「4 bit 余量现在是免费的」与 §6.4「算术噪声不是瓶颈」,
两者都是格式裁决(A2/A4,台账里的 🔴)的支撑;而 §6.4 的脚注**只讨论了噪声相关性假设**
(最多值 9 dB),**恰恰漏掉了值 73 dB 的那一维**。
**⇒ 这是 LESSONS B-4-③ 的原样复发**:一整套检验全过,却没有一条检查决定性的那一维,
因为没人问过「这套模型覆盖了哪些维度」。**D-4 被用在了系数/传函轴上(§9.3),没被用在噪声轴上。**

**修法**:
- ① §6.4 表格标题改为「**各节单位增益前提下**的链末噪声底」,并把「各节增益 = 1」列进工作点向量;
- ② 增补一行**按最坏合法增益配置**算的数(即上表 ④),与 PRD / 设计目标各自对表;
- ③ **⇒ 若 ④ 判为不可接受,处置属 D3/D4 的增益结构设计(把大增益放在链尾、或限制累计增益),
  ⛔ 不是改本件的格式** —— 我不替 D3/D4 裁,只要求这条不能留在"余量 52.9 dB"的表述下。

**复核方式**:我的复算脚本在 scratchpad(`critic_check_B.py`),不 import 被审件;
作者可用任何独立方法重算配置 ④,只需 `Σ_k mean|H_{k+1..N}|²`。

## MAJOR-3 · 厂家锚点与本件自选的乘法器模式矛盾:所选模式下 `RND` 是空操作,且舍入点对不上

**位置**:§5.2「硬件支持:`MRF = RND MRF` … **是指令修饰符,不额外花周期** [L2/厂家 Core PR §Round MRx Instruction]」;
§4.2「目标侧硬件支持:`MRF = SAT MRF`(两补码分数)」;与 §5.5「本文件按**整数模式**语义写(移位 27)」。

**直接观测(我读的是库内那份 PDF 原文,不是二手转述)**
`knowledge_base/adsp21569/bsp/sw_reference/SHARC+ Core Programming Reference…pdf`,§Round MRx Instruction:

> "The RND operation (MRF = RND MRF) **applies only to fractional results, integer results are not effected**.
>  This operation performs a round to nearest of the 80-bit MRF value **at bit 32**, for example, the MR1F-MR0F boundary."

同章 Figure 3-2 / §Multiplier Result Register:

> "…the 32-bit result … using bits 63–32 for a **fractional** result or bits 31–0 for an **integer** result."

**⇒ 两条独立的对不上**:
1. **模式**:本件 §5.5 明写按**整数模式**;而 `RND` **在整数模式下不生效**。
   ⇒ 「舍入是免费修饰符」这句在本件自选的模式下**不成立**。
2. **舍入点**:`RND` 舍在 **bit 32**;本件需要的重量化点是 **bit 27**(`CHDSP_ACC_TO_SMP_SHIFT`)。
   即使切到分数模式,舍入点仍不是 27(分数模式下移位改 26,见 X2)。
   ⇒ 目标侧要拿到本件规定的 RTN,须显式做 80-bit 移位 + 舍入 + 饱和序列,**那是要花周期的**。
3. **饱和同理**:Table 3-5 的六个饱和值都是**格式边界**(分数 → MR1F/MR0F 满位;整数 → MR0F 满位),
   不是"右移 27 之后再钳到 int32"。⇒ §4.2 的「目标侧硬件支持」也不是直接对应关系。
4. **§4.2 说"两补码分数"、§5.5 说"整数模式"** —— 本件内部对目标乘法器模式的两处表述互相矛盾。

**并且它与本件自己的 §10-X1 冲突**:X1 写「**本件零算力结论**。全部待 W1-C / 目标板,标 [L4/待验证]」;
而 §5.2 的「不额外花周期」与 §5.4 的「约 +40% 的 biquad 内循环 op 数」**都是算力结论,且都没有 L 标**。

**为什么是 MAJOR**:①它是本件唯一两条声称"目标侧免费"的话,而两条都会被 D13 算力预算直接消费
(C9:未在目标板实测的收益不得计入依据);②它使 `channel-dsp` 职责里那句「C → **bit-exact**」
在 tie 规则一级没有依据(见 MINOR-1);③**它是 D6-ag 的教科书形态**:「有来源」≠「在这个工作点上验证过」
—— 锚点有厂家出处,但没人问过"它在我们选的模式下还成立吗"。

**修法**:
- ① §5.2 / §4.2 的「硬件支持 / 不额外花周期」**降级为 [L4/待 CCES 实测]**,并原样引上面两段厂家原文;
- ② 把「目标乘法器模式(整数 vs 分数)」从 X2 的一个脚注提升为**本件的一个待定工作点**,
  因为它同时决定移位量(27/26)、`RND` 是否可用、`SAT` 的钳位点 —— 三件事,不是一件;
- ③ §5.4 的「+40%」补 L 标或删,与 X1 对齐(二选一,⛔ 不得并存)。

## MAJOR-5 · §9.3 的 LR8 行标了"(结构约束下)",而那个数实际走的是**自由量化** —— 恰好是本件自己判定为"巧合"的那一格

**代码事实**:CHK-5d 的 `hq` 来自 `to_fixed_bq(hp, &hq)` —— **b0/b1/b2 各自独立取整**,即**自由量化**。

**⇒ 表里那个"精确 0"就是那个巧合本身,不是结构约束的战果。**
结构约束的战果是同一段代码另一行的 **CHK-5t(单节)** 与 **CHK-5f(500/500)**。

**后果(具体、不夸大)**:**「本件强制的结构约束量化,在 LR8 四节级联下表现如何」这件事实际未测**,

## MAJOR-6 · 「第二轨(铁律七)」实为**同式转写**,不是独立方法

**位置**:约定文档 §7.3 与 §13「第二轨(铁律七)」行;`ref_fixed.py`。

**核实**:`ref_fixed.py:33-49` 的 `db_to_gain_py` 与 `chdsp_fixed.c:24-55` 是**逐步同构**的:
同样的 `K_Q40` 常数、同样的 `>>16 / >>32` 序列、同样的 `idx/lam` 拆分、同样的 `+half` 舍入、
同样的 `n-2` 移位;`EXP2` 表用同一条公式 `round(2^(i/128)·2^29)` 重建。
`ref_fixed.py:107-126` 的 `df1_ef` 同样是 `chdsp_biquad_df1` + `chdsp_acc_to_smp_r` 的逐行转写
(同 `(acc+half)>>27`、同 `r = acc − (y<<27)`、同 `(a1*r1)>>27`)。

**⇒「43009 点逐位相同」能证的是转写忠实(可抓表项转录错、移位顺序错);
⛔ 不能证算法对**(K 取错、舍入语义两边同错、移位口径两边同错,都会一致通过)。
这正是 critic memory 教训 ②:「双轨复算一致」必须先问两轨是否同式;同式一致 = 没复算。

**⚠ 但我要说清:实质没有塌。** 真正独立的那一轨**存在且两边都做了** ——
对 `pow(10, dB/20)` 的精度比对(C 轨 CHK-7/CHK-7b、py 轨 T1a 的 `worst_in`),
那是与实现无共用代码的解析参照。**⇒ 问题是措辞与定级,不是缺证据。**

**修法**:§7.3/§13 改写为
「T1 = **实现一致性核**(转写忠实,含阳性对照);**铁律七的独立轨 = 对解析式 `10^(dB/20)` 的精度比对**」;
两件事分两行报,⛔ 不合并成"双轨交叉核"一句。
