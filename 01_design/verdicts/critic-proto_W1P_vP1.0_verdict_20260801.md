### MAJOR-1 · `_level` 未补偿 Hann 相干增益,全频段系统性低读 **6.03 dB**;§4.3/F5 的「早 5.7dB」很可能是本缺陷的镜像

**位置**:`nhs.py:218-219`

```python
def _level(self, M, k):
    return 20 * np.log10(M[k] * 2.0 / NFFT + 1e-30) + self.cal
```

**事实**(实证,`probe1.py` P-1,四个 bin 中心频点):幅度 1.0(= 0 dBFS 峰值)的正弦,`_level` 读数 **−6.03 dBFS**,与频率无关。Hann 相干增益 = 0.5 ⇒ 正确折算应为 `4*M[k]/NFFT`,代码用 `2*M[k]/NFFT`。

**为什么是问题**:

1. 合同 **C12 明定**「T_panic 语义 = 检测 tap 点电平(**dBFS**)」。权威源的 dBFS 比真值低 6.03 dB ⇒ `T_panic=−6` 实际要求真值 **≈0 dBFS**(满幅正弦才触发)、`T_low=−45` 实际是 −39、`T_low_gr=−65` 实际是 −59。C12 软校验拿 host 侧真 dBFS 与 T_panic 比,**两边不是同一个刻度**。
2. **更重的一条**:§4.3 / FINDINGS F5 把「T_low_gr 实测失效临界 = 前向 **53.3dB**,比设计件算术 **59dB 早 5.7dB**」定稿,并据此立了通则「凡电平门 vs 增益结构的推导须按 bin 域折算;C12 软校验按总电平算会高估余量 9-16dB」,已作为 **P13 点单打向合同 C12**。
   把 6.03 dB 加回去:`results.txt` 的拟合 `峰bin电平 = −1.00×前向 − 11.6` ⇒ 真值 `= −1.00×前向 − 5.58` ⇒ 过 −65 的临界 = 前向 **59.4dB**,与设计件算术的 **59dB 差 0.4dB**。
   ⇒ **那 5.7dB 的"证伪"几乎完全等于原型自身的标定缺陷**,而不是"门比 bin、算术比总电平"这个概念差。
3. §4.1 的 B-F1 结论也是用 **tap RMS(−57.4dBFS)**与 bin 域门 T_low 直接比——**正是 §4.3 在两页后禁止的那件事**,在同一份文档里犯了。

**建议方向**:先修 `_level`(含是否要补 3 dB 的 RMS/峰值约定、抽取器带内跌落),再**重跑**标定段;然后重新判定 F5/F6 的结论还剩多少、P13 是否还要提。在此之前 §4.3 与 P13 应挂"待重测"。
