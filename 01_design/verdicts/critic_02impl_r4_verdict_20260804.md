# 三、lead 指定:攻击那层「没声明 `want` 即 FAIL」的自检

**它是什么**:
```bash
if [ -z "$want" ]; then
  echo "[FAIL] ⛔ 本闸门没有声明失败特征串(want)⇒ 判据退化成「任何非 0」"
  echo "       ⇒ 器械失效 ⇒ 本条元检查无意义(⛔ 不得当作通过)"
  fail=$((fail+1)); return; fi
```

## ✅ 它本身**不可能是假绿** —— 理由是结构性的

它是一个**纯字符串空判**,**不执行任何外部命令** ⇒ 不存在"命令跑不起来被误判成通过"的通道。
**⇒ 而这正是它与它所修的那个病的关键区别**:原病的根源是"用外部命令的退出码当判据";
这条自检没有外部命令,所以那条通道在它身上不存在。

## ✅ 而它对 DISQ 是黑名单这件事,是有免疫力的

我原本准备打的是「DISQ 是黑名单,黑名单必不完备」(如 `python3: can't open file`、
bash 语法错、OOM 137、timeout 124 都不在表里)。**⇒ 但这条打不动,因为判据是三层与:**
```
rc≠0 ∧ ¬DISQ ∧ match(want)
⇒ 一个不在 DISQ 里的"跑不起来"错误,它的输出也不会命中该闸门自己的 want
⇒ ⇒ 所以它会被【第三层白名单】挡下,报「红了,但不是它自己那条失败特征」
⇒ ∴ DISQ 只是把错误信息说得更准,真正的防线是 want 这个白名单 —— 白名单优于黑名单,选对了
```

## ⛔ 而残口在这里(一行可补)· **`want` 没有被校验为【非平凡】**

```
写 want="."  或 want=".*"  ⇒ 非空 ⇒ 通过自检 ⇒ 而它命中任何非空输出
⇒ 第三层白名单被架空,判据退回「rc≠0 ∧ ¬DISQ」
⇒ 那正是这条自检要防的"悄悄退回旧病",只是换了个方式:不是【不写 want】,是【写一个恒真的 want】
```
**⚠ 而我要说清严重度:这比原病【轻一档】** —— 即便 `want` 恒真,DISQ 那层仍在,
**我实证过的那个洞(拿走被测脚本)仍会被抓住**。⇒ 所以这是 **MINOR 级残口,不是 BLOCKER 未闭**。

**修法(一行)**:在空判之后加一条 —— `want` 不得匹配空串:
```bash
if printf '' | grep -qE "$want"; then  echo "[FAIL] $tag ⛔ want 恒真(匹配空串)⇒ 白名单被架空"; fail=$((fail+1)); return; fi
```
⇒ 现有 12 道闸门的 `want` 我逐条看过,**没有一条是平凡的**(如 G7 = `\[FAIL\]|不同|DIFF`,
G8 = `differ|DIFF|不同|不一致`)⇒ **当前无实际暴露,是防复发用的。**

## ⭐ 而 lead 问「我要的是修好这一次,它做的是让这一类不能再发生」—— 我的判断:**这个升级是对的,而且理由比它自己写的更强**

它给的理由是「将来有人加第 13 道却忘了写 want」。**⇒ 而更强的理由是它自曝的那件事:**
> 它给 G8 写的失败特征是「不一致」,而实际输出是「不同」⇒ 新判据第一次跑就把它自己抓了一次。

**⇒ 这条自曝是本轮最有价值的一句。** 它证明的不是"作者细心",是:
```
【内容判据】这一层【有分辨力】——它抓住的第一个对象是写它的人自己
⇒ 而一个第一次跑就抓住作者的判据,比一个第一次跑就全绿的判据,可信度高一个量级
⇒ ⇒ 这正是「阳性对照」的天然形态:不是造出来的,是撞出来的
```

# 三之二、⛔ MAJOR-1(新增)· `DISQ` 扫的是**整段输出**,不是【非 0 的那个原因】⇒ 会把**真的响了**的闸门判成"没跑起来"

**位置**:`check_gates_fire.sh:114-120`

```bash
out=$( ( cd "$w/02_impl" && eval "$cmd" ) 2>&1 ); rc=$?      # ← 整段 stdout+stderr
if [ $rc -eq 0 ]; then  ... 没有响 ... fi
if printf '%s' "$out" | grep -qE "$DISQ"; then ... 判「跑不起来」... fi   # ← 扫整段
if printf '%s' "$out" | grep -qE "$want"; then ... 判「真的响了」... fi
```
**⇒ `DISQ` 在 `want` 【之前】判,且扫的是整段输出 ⇒ 只要输出里**任何一处**出现
"no such file",哪怕闸门同时**确实**因为它自己那条特征而红了,也会被判成"没跑起来"。**

[PASS] base:runall  ← 阴性对照通过 ⇒ 排除我先前那次的并发污染

**(B) 而我手工复现 G10 的同一个变异,单独跑 `check_mutants_valid.sh`**:

**⇒ 我据这两条判定误判成立;⛔ 噪声成因待作者定位。**

## 若不修,下游会怎么错

1. **交付闸门在干净树上就是红的** ⇒ 而 `run_all.sh` 的红是"阻止交付"的那种红
   ⇒ **要么交付被永久阻塞,要么有人开始忽略它 —— 后者更危险。**
2. **它是"狼来了"的制造机**:一个会在正常情况下误报的闸门,会训练所有人不看它。
   ⇒ 而这正好抵消了这轮整改的全部收益。

## 修法(一行,改判定顺序即可)

```bash

elif printf '%s' "$out" | grep -qE "$DISQ"; then ... 判「跑不起来」...
else                                              ... 判「红了但不是它那条特征」...
```
**⇒ 语义上也更对**:`DISQ` 的作用是【解释为什么没命中 want】,不是【否决已经命中的 want】。
⇒ 顺带请作者定位 `/tmp/gates_j` 下 `build_mv/` 日志缺失的成因(可能与 `mkwork` 复制 `build_mv/` 后
