# 三、⭐ EXP-10b 裁定(lead 指定我判,并说不裁)

## ⚠ 先更正一处事实:lead 转给我的那个论证,**不在 `RETIREMENT_LOG.txt` 里**

lead 转述 `channel-dsp-2` 的立场是「退役理由**文不对题** —— 那条分支断言的是【可用性】不是【合规性】」。
**⇒ 我读了 `d34_chain/RETIREMENT_LOG.txt` 原文,它的实际立场比这【弱得多】**:
> 「⇒ **该理由本身站得住**(critic 也这么认为):对作用域未定义的规格断言符合性,确实不可判。
> ⇒ **⛔ 但它是【跑完之后】才写下的**……两条理由都不假,但**它们的证据力不同**。
> ⇒ ⛔ 本件**不替它翻案**,只把这件事记成正式记录,交 critic / CTO 判。」

**⇒ ∴ `channel-dsp-2` 主张的是【时序/证据力】,不是【文不对题】。**
**⇒ 那个"可用性 vs 合规性"的论证是在转述中出现的,而不在它引的那份文件里。**
⚠ 而这正是 lead 昨天刚立规矩要防的那件事(转述方要给路径)——
**给了路径是对的;而转述的内容与路径里的内容不一致,是这条规矩的下一层。**

## ⇒ 我的裁定:**两方都对了一半,而决定性的事实两方都没引**

### (1) 那条分支断言的是**可用性**,不是合规性 —— 我据原文判

`PREREG_D34_r9_addendum §2` 逐字:
```
EXP-10b 若 (b)/(c) 通过,重做拒绝率代理:**在 (b) 口径下**从 REF 还能加几段。
  预期    : ≥4 段
  证伪条件: <2 段 ⇒ **即便换频带口径**,日常调音仍会频繁撞拒绝
```
```
① 频带【被实验自己钉死】在 (b) ⇒ ⛔ 不等 CTO 定
② 被测量 = 「还能加几段」= 余量,⛔ 不是「合不合规」
③ 后果句 =「日常调音仍会频繁撞拒绝」= 可用性
④ 而「**即便换频带口径**」这半句,是刻意让结论对作用域歧义【免疫】的
⇒ ∴ 它断言的是【可用性】。r11 的退役理由(「对未定义作用域的规格断言符合性」)对它**文不对题**
```
**⇒ ∴ 在这一点上 `channel-dsp-2`(经 lead 转述的那个版本)是对的,而 `RETIREMENT_LOG` 自己**让步太多**了 ——
它写「该理由本身站得住」,而对 EXP-10b 它不站得住。**

### (2) ⛔ 但那条分支的**后果句本身是错的** —— 而推翻它的数据就在同一条检查里

`results_d34_r12.txt:279-282`(EXP-10b 自己的输出,四个下沿):
```
下沿 100 Hz ⇒ 可再追加 **0** 段     ← 证伪条件在这一格命中(0 < 2)
下沿 125 Hz ⇒ 可再追加 **3** 段
下沿 150 Hz ⇒ 可再追加 **8** 段     ← ⭐
下沿 200 Hz ⇒ 可再追加 **8** 段
```
**⇒ 分支的后果句是「**即便换频带口径**,日常调音仍会频繁撞拒绝」。**
**⇒ 而换到 150 Hz,可加 8 段 ⇒ 那句话被【同一条检查自己的数据】证伪。**

```
⇒ ∴ 该预注册分支的缺陷是【具体且可指名的】:
   它把结论从【一个候选频带】(b) 泛化到了【任何频带】("即便换频带口径"),
   而它自己后来扩成四个下沿的测量,直接推翻了那个泛化
⇒ ⛔ 这不是"预注册病态"那种含糊说法,是**过度泛化**——而两者的整改动作不同
```

### (3) ⇒ ∴ 三条被同一个理由退役的检查,**是两种不同的东西**

| 退役项 | 它断言什么 | r11 那条理由适用吗 |
|---|---|---|
| **EXP-10a2** | REF 在 (b) 下全链 **12.835 ms ≤ 12** ⇒ **合规性** | ✅ **适用** —— 12 ms 是不是 (b) 带的门,确实取决于 CTO |
| **EXP-10b** | (b) 下**还能加几段** ⇒ **可用性**,频带自钉、且带免疫句 | ⛔ **不适用**(见 (1)) |
| **EXP-9c** | (a) 下还能加几段 ⇒ **可用性**;而其 r8 预注册**已把它条件化于 EXP-10** | ⛔ 不适用;正确标签是**「被 EXP-10b 取代」**,不是「不可判」 |

**⇒ ⭐ ∴ 这是【一条理由写了一次,套在三条不同性质的检查上】。**
**⇒ 而两方都没发现这一点 —— 因为两方都在争"那条理由对不对",没有人问"它对哪几条成立"。**
**⇒ ⚠ 而这与我自己 `CHK-D3` 那次是同一形状**:按一个标签处理一组,没有逐条开箱。
**⇒ 我昨天为此给自己立了规矩,而这次是别人踩同一个坑 —— 说明那条规矩不该只归我。**

## ⇒ 处置(三条,分开)

```
EXP-10a2  退役【有效】,理由成立 ⇒ 维持
EXP-10b   退役的【结果】可接受(把决策输入交给 EXP-11 的 f_lo* 是对的)
          ⛔ 但【理由】错、且【被触发的分支未被执行】这件事必须记
          ⇒ 正确记法:**分支被触发 ⇒ 其后果句被同一检查的更宽数据证伪
             ⇒ 预注册缺陷 = 从一个候选频带过度泛化到"任何频带"**
          ⛔ 不记作「事后合理化」(那会指向错误的整改:去查动机)
          ⛔ 也不记作「执行分支」(其后果句已被证伪,执行它会得到一个假结论)
EXP-9c    退役【有效】,而标签应改为「**被 EXP-10b 取代**」,不是「作用域未定义 ⇒ 不可判」
```

**⇒ 而 lead 那个默认值(「按分支被触发而未执行记,由证据放松」)—— 我判它【已被证据放松】,
放松后的记法就是上面 EXP-10b 那三行。⇒ 你的默认取严是对的,而现在有证据了。**
