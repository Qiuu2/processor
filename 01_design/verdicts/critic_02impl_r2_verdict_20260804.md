# 三、⛔ 作者对我的更正:**成立。我 r1 / D3D4 的那条建议在噪声轴上方向反了**

**位置**:`critic_D3D4_CHAIN_v0.1_verdict_20260804.md` MAJOR-3 修法 ④,原文
> 「⇒ 若判为不可接受,处置属增益结构设计(**把大增益放在链尾**、或限制累计增益)」

**我独立复算作者给的式子** `链末噪声 = q²·[G²·k + (N−k)]`(k = 增益**上游**的量化器数,N=28):

| 增益位置 | 链末噪声(rel q²) | 链末 SNR(rel S²/q²) |
|---|---|---|
| **链首**(k=0) | **+14.47 dB** | **+5.53 dB** |
| 链中(k=14) | +31.50 dB | −11.50 dB |
| **链尾**(k=28) | **+34.47 dB** | **−14.47 dB** |

```
链尾 − 链首 = +20.00 dB,而 G = +20 dB ⇒ 差值恰等于增益本身(G=+6/+10 dB 时同样成立)
```
**⇒ 机理:增益放在链尾 ⇒ 它上游【全部】量化器的噪声都被 G 放大;放在链首 ⇒ 一个都不放大。**
**⇒ ∴ 在噪声轴上「增益越靠前越好」,而我写的是相反的。**

**⇒ 这条错误的来源我要说清:它不是我原创的,是我从前任 critic 对前置件的 MAJOR-2 修法 ③
原样承接下来的措辞,而我没有验它就复述了一遍。**
**⇒ 这正是我在四份 verdict 里反复打的那个形状:一句话被转述时没有人重新验它。⇒ 我自己也犯了。**

**⚠ 而作者的处置我要表扬**:它**明确只证了噪声轴,并写明饱和轴相反,⛔ 不主张推翻我的建议**。
**这个克制是对的** —— 两条轴确实冲突:
```
噪声轴  增益靠前更好(上游噪声不被放大)
饱和轴  增益靠后更好(链内电平低,不越 Q4.27 的 24.08 dB 余量)—— 即 CHK-C1b 测的那件事
⇒ ∴ 正确的表述不是"放链尾"也不是"放链首",是【一个 headroom-vs-噪声的权衡】,
   而我把其中一侧当成了答案。
```
**⇒ 我已另出勘误件更正 D3/D4 verdict(见 `..._erratum1.md`)。**
