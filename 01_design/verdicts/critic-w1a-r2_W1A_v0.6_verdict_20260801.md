# 1. MAJOR

## A-M1 · §0 T1 行的"上界担保 7.3"与同行"敞口至 8.51"不能同真;§2.1 三口径连体缺 8.51 情景,与 DEC-0009 的 40-50% 两处并存

**位置**:§0 分档表 T1 行(:21)、§2.1 三口径连体段(:87-90)、对照 `decisions_log` DEC-0009 风险声明。

**事实**
1. §0 T1 行「计入预算值」栏写:「其"悲观性"**无板证**,风险敞口 = **若板测落 8.51 量级则本档 ×4.3**,V-1 收口」;同一行「上界担保」栏写:「**7.3 cyc/MAC**:竞品 32ch×8段EQ=61.44 MMAC/s 跑在 SHARC 21489(~450MHz)已量产 [L4/竞品手册]…**此上界适用于本档全部行项(F2 修正)**」。
   ⇒ 若 7.3 是**担保**上界,则"板测落 8.51"在本档内**不可能发生**;若板测可能落 8.51,则 7.3 不是担保。**两句互斥,文中未调和。**
2. §2.1 三口径连体 = 计入 11.7% / 期望 ~6% / **上界 22.7%**,上界用的乘数是 **7.3**(我复算:T1 三行 20,480+12,288+1,024 = 33,792 MAC/帧 ×7.3 = 246,682;T2/T3 按计入值 55,562;合计 302,244 = 22.67% ✓ 算术全对)。
3. 但按同文件承认的 **8.51** 复算:T1 三行按 op 计(36,864+12,288+1,024 = 50,176)×8.51 = 426,998,加 T2/T3 55,562 → **≈482,560 cyc/帧 ≈ 36.2%**(T2 另无板证上界,实际更高)。
4. `decisions_log` DEC-0009 风险声明原文:「若 W1-C 实测落在 8.51 量级,**AFC 占比将升至 ~40-50%**」。⇒ **台账写 40-50%,W1-A 的"上界"写 22.7%,且 W1-A 未引用该情景。**

**为什么是问题**
- D13 汇总会引用 §2.1 的三口径连体,而**库内唯一同族 L1 板测数据(8.51)对应的情景不在表内**。L 级权重红线要求 L1 > L4;这里一个 [L4/竞品反推] 的数被冠以"担保上界",而一个 [L1] 的数落在它之上却只出现在散文里。
- 这与 critic-w1 **F2** 同族:上次是"只重定价了一行就冠名合计上界",这次是"用一个低于已有 L1 观测的 [L4] 乘数冠名上界担保"。前科已在案,同一位置第二次出问题。
- 后果方向:**低估**。若真值落 8.51,AEC×N(D13 的真正裁决点)的可用余量会被系统性高估。

**修法方向**:三口径连体加**第四口径**(8.51 锚定情景),或把 7.3 从"上界担保"改为"竞品反推的**结构类比参考值**"并说明它与 8.51 为何不可比(若确不可比,把"敞口 ×4.3"一句同步改写,不能两句并存)。无论哪条,**须与 DEC-0009 的 40-50% 对齐口径**。
