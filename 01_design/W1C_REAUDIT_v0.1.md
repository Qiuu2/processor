## §2 ⛔ 原本就是假绿的(与性质变更无关,旧性质下也不成立)

### 2.1 B-1 ⛔⛔ `t1a_coeffs` 声明了、传进去了,**从未被赋值** ⇒ 全零

```
t1a_biquad.c:49   static float pm t1a_coeffs[5 * T1A_MAX_BIQUADS];   /* 无初始化列表 */
全文件 grep `t1a_coeffs` ⇒ 命中 4 处::49 声明、:84 注释、:122 传参、:126 传参
⇒ ⛔ **零处写入**。静态存储期 ⇒ 全部 0.0f
```
**逐条后果:**
```
① 输出恒为 0 ⇒ `chk = (int32_t)(out[0]*1000) ^ (int32_t)(out[window-1]*1000)` = 0 ^ 0 = **0**
   ⇒ T1a 的 36 行 checksum **全为 0**
② 而 `w1c_selfcheck.h` 自己的判读规则写着:
   「换了不同参数之后 checksum 长期恒为同一个值、**尤其恒为 0**——这才说明代码可能被优化掉,
     **按"测不到"处理,不要采信该行周期数**」
   ⇒ ⇒ **该内核的守卫会判它自己的全部行不可采信** —— 而且是因为一个它没在防的原因
③ ⭐ 更坏的是**守卫失去了分辨力**:`chk ≡ 0` 使「被 DCE 掉」与「系数是零」两种情形**不可区分**
   ⇒ 这正是假绿分类 ①(测了个恒真的性质)的镜像:该判据在 T1a 上**恒假**
   ⇒ 恒假的判据与恒真的判据一样没用,而且更坏 —— 它会把人引向一个错误的诊断(以为编译器优化掉了)
④ 周期数本身**可能仍然有效**(定长循环、无数据相关分支)⇒ ⚠ 但这是 **[L4/待验证]**:
   零操作数在浮点单元上是否等时,我方无工具链可核 ⇒ ⛔ 不得假定
```
**⇒ 判:T1a 现状**不可用**。而修法极小(填一组真实系数),见交付② §2.1。**

### 2.2 B-2 ⛔ 时钟自检**能 FAIL,而不阻止任何事**

⇒ 自查一句「这个检查失败时会阻止什么?」⇒ 答:**什么也不阻止,只打印一行字**
⇒ ∴ 按 orchestrator 侧那条:**它是输出,不是检查**
⇒ 且它踩中 LESSONS D-3(加了报警必须同时接上处置)—— 该文件自己写着"A FAIL here invalidates
  EVERY other line of output",却没有让它 invalidate 任何一行

**⭐ 而更隐蔽的一半(这一条我认为比上面那半更危险)**:

### 2.4 B-4 ⚠ L1/L2 两臂"真的不同内存"从未被断言(风险,非已证假绿)

```
✅ 我核过 `system/startup_ldf/app.ldf`:`seg_l2` **确实存在**(与 seg_l1_block0..3 并列)
   ⇒ ∴ 不是"pragma 名字根本不存在"这种低级情形
⚠ 而仍未关的风险:这些 L2 数组是**无初始化列表的静态数组**(走 bsz/noinit 路径),
   而 LDF 里另有 `seg_l2_bsz_data` / `seg_l2_noinit_data` 两个**分开的**输入段名
   ⇒ 「`#pragma section("seg_l2")` 的未初始化数组最终落在哪」我方**无工具链可核** ⇒ [L4/待验证]
⇒ 若它静默落回 L1,则 L1 臂与 L2 臂是**同一种内存** = 假绿分类 ②(两臂被构造成相同)
⇒ ⭐ 而这个风险可以**一次性关掉且成本≈0**:运行时打印两臂缓冲的地址(见交付② §2.3)
   LDF 给了硬边界:L1 = 0x0009_0000…0x0039_bfff;L2 = 0x2000_0000…0x200f_ffff
```

✅ 两处**都写了注释披露**,且 T3 的理由是对的(不重置会让轨老死 ⇒ 退化成空扫描 ⇒ 低估)

### 4.2 D-2 ⭐⭐ **T1a 测的是浮点通路** —— 在新性质下,它测的不是我们缺的那个数

```
`<filter.h>` 的签名(该文件 :78-80 逐字抄录):
   biquad(const dm float *in, dm float *out, const pm float *coeffs, dm float *state, int, int)
                     ^^^^^              ^^^^^                ^^^^^          ^^^^^
⇒ 四个数据参数**全是 float** ⇒ T1a 跑的是**浮点 biquad**
而 DEC-0006 锁**定点**口径;DEC-0023 要的是**第一个定点锚点**
⇒ ⇒ ∴ **T1a 在当前性质下,无论跑得多干净,都产不出我们缺的那个数**
```
**⇒ 而这不等于"删掉 T1a"。它换一个位置就有用:**
```
旧定位:DEC-0009/0014 的**主口径点**(拿它去回填算力预算)
新定位:⭐ **尺子标定** —— 用厂家**已公布**的浮点值(2.5 cyc/biquad)去验证
        「我们这套测量方法在这块板上能不能测准一个已知答案」
        (= LESSONS A-3「先把尺子验到能信,再用它量东西」的正用)
⇒ 它从"产出锚点的内核"变成"验证测量方法的内核"。**保留,降级,改判据**(交付② §3.1)
```
**⇒ 而真正的定点锚点内核【本件里不存在】,须新增**(交付② §2.1 的 T1a-fx)。
⚠ 且它**不应该**再去调 ADI 的库函数:该文件自己就写着
「我方陷波器组**系数时变、每通道独立状态**,实际实现可能更差」
⇒ **定点锚点要测的是【我方将要落地的那份 C 代码形态】**,不是厂家的优化库。

## §5b ⭐ 新判据的后果(lead 2026-08-05 更正后补;⚠ 本节改的是**判据**,§1–§5 结论不变)

> lead 更正:判据不是「它能不能验证 2.5 cyc/biquad」,而是「它能不能**产出一个可信的定点绝对值**」。
> 并给出理由:**对比测量可以靠两边同样的系统性误差自洽;绝对值不行。**

**⇒ 我核了这条理由,它成立,而且它把回审结论**推得更远**:**

| 原判(§1) | 在新判据下 |
|---|---|
| B-1 系数全零 | **不变**(仍是 ⛔),且更致命:绝对值没有"两边相消"可依赖 |
| B-2 尺子闸不阻断 | **升级**:对比测量里尺子偏 10% 两边同偏、比值不变;**绝对值直接偏 10%** |
| B-3 载荷扫描无判据 | **升级为最重的一条**:绝对值 = 拟合斜率 `b`;而 v0.1 报的是 `cycles/8`,**把每调用固定开销 a 摊进了 b** ⇒ 那正是"绝对值"最容易错的地方 |
| B-4 内存臂 | 不变(⚠) |
| B-5 热循环污染 | **升级**:对比里两臂同污染可相消;绝对值**直接被抬高** ⇒ 必须扣除,不能只披露 |
| D-2 T1a 是浮点 | **不变**(⛔),而 T1a-float 的**定位再变一次** —— 见下 |

**⇒ ⭐ 而最重要的一条改判:`T1a-float` 从「锦上添花的尺子标定」升为「T1a-fx 的承重前提」。**
```
理由正是 lead 那句话的逆用:
  绝对值不能靠"两边同样的系统性误差"自洽 ⇒ ∴ **必须有一个带【已知答案】的臂,把共享误差钉住**
  而全盘只有一个带已知答案的量:EE-408 的浮点 2.5 cyc/biquad
  float 臂与 fixed 臂共享:同一个 timer、同一套循环、同一份内存放置、同一份调用开销
  ⇒ float 臂通过 ⇒ 这些共享项的系统性误差从【看不见】变成【已测】
  ⇒ float 臂不过 ⇒ fixed 臂的**绝对值无效**(⛔ 而不是"仅供参考")
⇒ ∴ 执行顺序要改:T1a-float **必须先跑且必须过**,才轮到 T1a-fx 出数(交付② §5 已改)
```
